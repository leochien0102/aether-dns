## 1. 根因、修复及范围

`src/lists.rs` 原先按名单原始字节建立 HashMap，查询也按原始字节查找，因此同域名的 ASCII 大小写变体成为不同键，甚至绕过同后缀优先级或最长后缀匹配。

最小修复仅修改名单键：

1. `load`：仍先执行原有 `check_name`，将有效且截断后的字节切片通过 `to_ascii_lowercase()` 建键，继续使用 `entry(...).or_insert(tag)`。按后声明自定义组、gfw、chn 的原装载顺序保留高优先级标签。
2. `Router::resolve`：仍先保留最后八个标签，仅生成一份 ASCII 小写查询键；最长后缀到最短后缀的循环借用该键的切片做 HashMap 查找，不扫描名单、不按各后缀重复分配。
3. 非 ASCII 字节保持原样，不调用 Unicode 小写化、不转换文件格式、不改写名单文件。旧 `case_sensitive` 测试改为 `ascii_case_insensitive`；`src/lists.rs` API 注释及 `docs/tasks/m2.md` 两处原大小写敏感说明同步更新，其他历史约定不变。

调用端已核对：兼容入口 `lists::resolve` 委托给 `Router::load(...).resolve(...)`；服务器 `Routing::route` 将已解析名称去除最终根点后调用同一 Router，UDP/TCP 使用同一匹配实现。未修改服务器、DNS 报文处理、应答缓存、判定缓存、上游 ID、Netlink、配置或依赖。

原有最后八标签、最长后缀、标签边界、无效名单条目处理、缺文件跳过、未命中默认值均保留。大小写归一化只改变匹配键，不改变报文 Question。
