## 修复

`question_key()` 要求单 Question、完整且不压缩的 QNAME（含根不超过 255 字节），按标签仅折叠内容中的 ASCII A–Z。标签长度、根终止符、非 ASCII 字节、QTYPE/QCLASS 原样保留；没有对整个 Question 小写化。

`get/add/begin_refresh/finish_refresh` 均调用同一键函数；LRU 索引、替换/淘汰/过期删除、零 TTL 清除、刷新去重与失败冷却均沿用该键。容量、stale 时窗、刷新阈值、最多四个预约和五秒失败冷却策略未变。

准入同时检查应答的规范化 Question 与查询完全相同：这保证未压缩布局、标签边界、长度及数字字段兼容。无法安全等长回显的条目（包括压缩 Question）不准入。保留既有应答检查及 TTL 扫描。

命中先克隆 `Entry.response`，只在副本中等长覆盖本次完整原始 Question、恢复本次 ID、按既有偏移扣减 TTL。共享 Entry 不被客户端的大小写或 ID 污染；压缩 Answer 指向 Question 的指针不移动。

没有改名单、VerdictCache、上游校验、Netlink、依赖或设备设置。核对调用链：`src/server.rs` 命中/预约仍在同一锁内，正常转发和后台刷新仍分别通过 `add/finish_refresh` 写入。

进程内真实 DNS 服务 + `127.0.0.1` UDP/TCP 假上游，关闭任何真实设备依赖，固定注入时钟。交替查询 `x/X`，客户端 ID 为 100–107，前后交替 UDP/TCP。每次断言 ID 与完整 Question 字节相同、Answer 压缩指针仍为 `c0 0c`、可解析地址仍为 `1.2.3.4` 和 `2001:db8::2`。

这是 fresh **应答缓存**复用，不是 T16.100 的“只命中判定后仍转发”：首次以外没有上游请求。时钟范围内也未触发 refresh-ahead。

其他专项断言：

- 多标签 `FoO.BaR/fOo.bAr` 连续八次交替读取：整个报文与手工预期逐字节比较，仅 ID、Question、TTL 允许改变；压缩 Answer 及 TTL 偏移不变。容量为 1。
- QTYPE 的 `0x0041/0x0061`、QCLASS 的 `0x0041/0x0061` 分别保持独立。
- 非 ASCII `c3 89/c3 a9` 不合并；单标签 `A.B` 与两个标签 `a/b` 不合并；标签内零字节与根不混淆。根、非 ASCII 标签中的 ASCII、含零字节/点字节标签支持正确回显。
- stale 变体仍回显本次完整 Question，所有普通 RR TTL 为零。
- 跨大小写重复预约被拒；以另一个大小写完成失败后共享冷却，4999 ms 拒绝、5000 ms 允许；成功完成刷新由两个变体共用。
- 跨大小写零 TTL 刷新与直接 add 均清除旧条目；精确 stale 截止时刻失效。
- 容量 2 下大小写覆盖不挤掉另一个键；变体命中更新同一 LRU 节点，随后正确淘汰最久未使用条目。
- 不匹配应答 Question、可解析但布局不兼容的压缩根 Question、所有不完整查询前缀均安全拒绝。

既有刷新上限测试原先给五个不同查询复用了 `x` 的应答，这是不匹配 Question 的无效夹具；改为每个查询生成匹配应答，继续验证最多四个预约及失败释放。原先断言 `x/X` 为不同键的旧测试改用真正不同域名 `x/y`，大小写共享由新专项覆盖。
