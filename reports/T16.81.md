## 1. 改动说明

1. **`Cargo.toml`**：
   - 新增 `[profile.release]` 并设置 `strip = "symbols"`，使未来所有 `cargo build --release` 产物在链接产出阶段即剥离静态符号表（`.symtab` / `.strtab`），不再依赖下游重复 strip。
   - 未设置或修改 `dev` / `test` profile，未改动 `panic`、`opt-level`、`lto` 或 `version`。
2. **`tests/ci/check-stripped.sh`**（最小共享校验脚本）：
   - 使用 `LC_ALL=C readelf -SW <elf>` 读取待检 ELF 的实际 section headers，不通过匹配 `file` 输出中的 `stripped` 子串来判断（避免 `not stripped` 误匹配）。
   - 以下任意条件均返回非零退出码（fail-closed）：
     - 参数缺失、文件不存在或不可读；
     - `readelf -SW` 执行失败（如非 ELF 文件、损坏文件或工具报错）；
     - 读不到有效 section headers（如 `Section Headers:` 缺失或无非 `NULL` 节头）；
     - 节头表中仍存在名称为 `.symtab` 或类型为 `SYMTAB` 的静态符号表。
3. **`.github/workflows/release.yml`**：
   - 未新增 CI job、未新增外部依赖、未增加第二轮 `strip`；
   - 在现有四处二进制校验步骤中复用 `sh tests/ci/check-stripped.sh`，覆盖待上传裸 ELF 及包内二进制：
     - `binaries` job：`Build static binary`（双架构矩阵 `x86_64`、`aarch64_generic`）
     - `verify` job：`Prepare and check raw binary assets`（双架构待上传裸二进制）
     - `verify` job：`Check apk payloads (metadata, version and static linkage)`
     - `verify` job：`Check ipk payloads (versions and static linkage)`
   - 完整保留原有静态链接检查（`file` 含 `statically linked`、`readelf -d` 不含 `NEEDED`）、版本串检查（`-V` 与 `tests/ci/check-version.sh`）以及双架构执行检查（`x86_64` 直接执行、`aarch64_generic` 经 `qemu-aarch64` / `qemu-aarch64-static` 执行）。

## 3. 影响说明、旧资产口径与未验证项

1. **对符号化诊断的影响**：
   - 未来 release 产物剥离 `.symtab` / `.strtab` 后，直接对发布 ELF 使用 `nm`、`objdump`、`perf` 或离线裸地址反查将不再看到内部函数静态符号名；若需对线上崩溃或采样地址做符号化诊断，需按同版本 commit 与构建参数在带符号环境复现构建，或另行保留调试构件。
   - `dev` 与 `test` profile 未改动，本地开发调试与测试堆栈信息不受影响；`strip = "symbols"` 亦不改动运行时栈展开段（`.eh_frame` 等）。
2. **未改旧资产**：
   - 本变更仅作用于未来新构建，不替换或重传 `v1.0.2` 及任何已发布 Release 资产，未修改 `Cargo.toml` / `openwrt/Makefile` 版本号，也未改动下游 `aether-proxy` 钉定哈希。
3. **未验证项（环境缺口如实记录）**：
   - 本机系统 Rust 工具链（`rustc 1.93.1` 源码包构建，无 `rustup`）仅安装了 `x86_64-unknown-linux-gnu` 标准库，缺少 `x86_64-unknown-linux-musl` 与 `aarch64-unknown-linux-musl` target stdlib，且缺少 `musl-gcc`、aarch64 musl 交叉链接器与 `qemu-aarch64` / `qemu-aarch64-static`。
   - 因此本机**未**实构两个正式静态 musl 目标（`x86_64-unknown-linux-musl`、`aarch64-unknown-linux-musl`），**未**做 `aarch64` 运行时仿真执行，也**未**在远端 GitHub Actions 实跑 `release.yml` 与 OpenWrt SDK `.ipk`/`.apk` 打包流程。上述项需在后续推送并在 GitHub Actions 触发 `Release` 工作流（如 `workflow_dispatch` 或正式发版 tag）时实跑确认。
