## 实现

1. `reply_write` 沿用既有响应、路由、集合名和 IPv4 筛选逻辑，生成拥有所有权的集合名与地址列表。无集合、无可写 IP、坏响应等情形在申请额度前返回。包内地址去重保留，不做跨请求去重。
2. 独立静态 `IP_WRITE_PERMITS`，上限 **8**，限制全进程所有服务实例的运行中及已投递写任务总数，独立于 `IP_TEST_PERMITS`。
3. `try_acquire` 成功后才能 `spawn_blocking`。permit 移入闭包，覆盖 mutex 等待和同步 Netlink 调用；取消 async 等待者不会归还仍运行/排队任务的额度。
4. 等待 JoinHandle 完成；普通写错误沿用原告警并保留 DNS 应答，阻塞任务 join 失败也不替换 DNS 应答。满额直接跳过，无逐包 overload 告警。
5. `forward` 的实时与缓存命中路径都 await 此入口；没有缓存锁或判定锁跨越该 await。后台 refresh 仍只更新缓存，不写集合。同步写入口仅留给既有 `nft_write` 测试（`cfg(test)`），生产转发不再调用同步入口。

## 同步屏障证据（模拟 writer，不是真内核阻塞）

新增专项 `write_barriers_live_cache_overload_cancellation_shutdown_and_recovery`：

- 显式 `new_current_thread` runtime，阻塞池只设一个工作线程；真实 loopback UDP DNS 客户端/服务/假上游。
- writer 用 `Notify` 确认已进入同步 `Condvar` 屏障；主测试未开屏障前，writer 不可能返回。
- **实时与缓存命中分别验证**：进入 writer 后，发送无需 IPv4 写入的 AAAA 请求并收到正确应答；屏障仍关闭，原 A 客户端 `try_recv` 为 `WouldBlock`，证明该等的应答没有先发。打开屏障，注入写错误，收到逐字节正确的原 DNS 应答。
- 两轮 writer 次数分别为 1、2；两轮结束前上游请求总数始终为 2（A、AAAA 各一次），证明缓存命中再次尝试写，且没有再次访问上游。
- 一个运行任务加七个明确 poll 到 Pending 的任务填满额度。额外写调用和回环 A 请求直接完成，writer 次数不增加；原被接纳的 A 请求依然没有应答。
- 丢弃七个等待 future，并关停拥有运行中等待者的服务；服务停止时屏障仍关闭。新服务实例发来的 A 请求仍因全进程满额而跳过写，证明取消/服务停止未提前释放额度。
- 打开屏障，以单阻塞线程队列中的 marker 等待先前所有任务实际完成。调用数恰增加七，证明满额时没有额外入队。随后缓存命中能再次写入，证明失败/满额后恢复，无永久去重。
- 时序断言不依赖 sleep；独立 OS watchdog 仅用于阻塞 reactor 回归时在 30 秒内终止测试，不用它判断正常先后次序。专项额外重复 10 次均通过。

这证明既有同步 Netlink 后端在当前隔离内核上的写入/错误行为，不证明真实 Netlink 会按模拟屏障的方式阻塞，也不是新异步入口到真实 nft 的端到端时序实验。新入口的有界、等待、取消与反应堆可用性证据来自前述同步屏障专项，两类证据不混用。

## 边界与风险

- 服务停止可以取消 DNS 等待者，但不能强杀正在运行的同步 syscall；底层写任务保持额度直至真正退出。Tokio runtime 销毁可能仍等待阻塞任务；没有改变进程/Netlink 的既有预算。
- 满额时按 best-effort 丢弃本次写，不承诺每个应答都写成功；后续缓存命中可再尝试。
- 没有改 OpenWrt 内核，也没有目标设备实测。未合 main、未推送、未打 tag、未发版、未动设备。
