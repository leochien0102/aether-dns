## 1. 设计与实现

1. **全进程 UDP 监听器共享有限额度，与 TCP 连接额度独立（`src/server.rs`）**
   - 在 `run_with_limits` 中、进入 `for socket in sockets` 循环前创建单一共享信号量 `Arc<tokio::sync::Semaphore>::new(max_udp_queries)`，所有 `bind-addr × bind-port` UDP 监听器共享同一额度池；`tcp_permits` 保持为独立信号量，互不影响。
   - 保留 `run` / `run_with_cache_clock` / `run_with_tcp_limit` 既有签名与行为，不新增依赖、不新增配置项。
   - **生产默认上限**：`DEFAULT_MAX_UDP_QUERIES = 256`。
     - **选择理由**：面向 OpenWrt 家庭/SOHO 路由器（常见 128–512 MiB 内存、默认 `ulimit -n` 为 1024）。UDP 是局域网主要 DNS 传输，终端/浏览器常并发发出 A/AAAA/HTTPS 突发查询，因此 256 相比 TCP 上限（128）与 `dnsmasq` 默认 `--dns-forward-max=150` 留有更充裕的突发余量；同时即便在双上游探测（`RouteTag::None` 每次在途查询最多同时开启 2 个上游 socket）场景下，256 满载时上游 FD 峰值约 ~512，连同 TCP（128）与监听 socket 仍远低于 1024 FD 上限。此上限用于约束 UDP 在途查询任务并发，**不承诺进程内存总上限**（缓存、verdict、上游缓冲及运行时本身仍占内存）。
2. **复制报文与派生前决断、空闲不预占、满额直接丢弃**
   - 空闲 UDP 监听器仅在 `tokio::select!` 中等待 `shutdown.changed()`、`queries.join_next()` 与 `socket.recv_from(&mut buffer)`，**不提前占用任何额度**（即便监听器数量大于额度，单个活跃监听器也可使用全部额度）。
   - `recv_from` 返回后直接对借用切片 `&buffer[..len]` 执行零分配 `dns::check_query(packet)`，非法报文直接丢弃不占额度；合法请求在 `packet.to_vec()`（复制出任务私有报文）和 `queries.spawn(...)` **之前**调用 `udp_permits.clone().try_acquire_owned()`：
     - **取到额度**：包装为 RAII 守卫 `AdmissionPermit` 并移入任务，覆盖 `handle_query`、`dns::enforce_udp_limit` 与 `send(&socket, peer, &response).await` 全流程。
     - **满额丢弃**：不复制报文、不派生等待任务、不排队、不触碰上游或缓存、不逐包打印错误，直接 `continue` 回到 `tokio::select!`，既不阻塞 TCP 也不阻塞关停信号。
3. **全退出路径释放与边界保持**
   - `AdmissionPermit` 在 `Drop` 中先归还 `OwnedSemaphorePermit` 再递减观察计数；无论查询正常回复结束、无回复提前返回、发送出错还是在 500 ms 全局退出预算到期后被取消，额度均自动归还。
   - 未改动 TCP 接入策略、上游尝试与后台刷新策略、缓存、UDP 响应限长（`udp_budget`/`enforce_udp_limit`）或全局 500 ms 关停退出预算。

## 2. 观察点、生产值与测试值

- **生产默认值**：`DEFAULT_MAX_UDP_QUERIES = 256`（TCP 保持 `DEFAULT_MAX_TCP_CONNECTIONS = 128`）。
- **测试配置值**：
  - 跨监听器共享、空闲不预占、TCP 独立性与释放恢复测试：`max_udp_queries = 2`（4 个监听器：`127.0.0.1`、`127.0.0.2` × 2 端口，额度 `<` 监听器数；TCP 保持 `DEFAULT_MAX_TCP_CONNECTIONS = 128`）。
  - 满额关停收敛测试：`max_udp_queries = 2`（2 个监听器：`127.0.0.1` × 2 端口）。
- **应用层与上游双重观测**：
  - 通过 `run_with_limits` 注入测试用 `watch::Sender<UdpAdmissionStats>`（生产路径为 `None`，零额外开销），观测 `admitted`、`active`、`peak_active` 与 `rejected`。
  - 配合可控本机 UDP 上游通道（`mpsc::UnboundedReceiver`）作为屏障，验证已接纳查询抵达上游、满额丢弃的数据报既未增加 `admitted` 也未发出任何上游请求（不以客户端收不到回复作为唯一证据）。

## 3. 验证结果

1. **专项测试**：`cargo test --locked --offline --test udp_admission -- --nocapture`
   - **7 passed, 0 failed, 0 ignored**（耗时 0.51s）
   - 关键实测记录：
     - `default_udp_limit_is_bounded_and_independent_of_tcp`：确认 `DEFAULT_MAX_UDP_QUERIES == 256`、`DEFAULT_MAX_TCP_CONNECTIONS == 128`。
     - `shared_quota_across_listeners_tcp_independent_and_recovery`：
       - `shared_udp_quota: listeners=4 test_limit=2 prod_limit=256 admitted=5 peak_active=2 rejected=2`
       - 验证 4 监听器共享 2 额度时：单监听器可独立占满 2 额度（其余 3 空闲监听器不预占）；畸形 UDP 报文不占额度；跨 2 监听器各占 1 额度并由上游屏障滞留后，再向第 3 及原监听器发送的 2 个 UDP 查询被直接丢弃（`rejected == 2`、`admitted` 保持 4、`peak_active == 2`、上游无额外请求）；满额期间经由第 3 监听器的正常 TCP 查询顺利抵达上游并返回完整应答；解除 1 个上游屏障后额度归还（`active == 1`），向第 4 监听器发送的后续 UDP 查询立即接纳并成功返回，全部释放后 `active == 0`。
     - `shutdown_converges_within_budget_when_at_capacity`：
       - `shutdown_udp_at_capacity: drain=500.920991ms active_after=0 peak_active=2 rejected=1`
