### 重传保护：对实际 workflow 脚本做 mock

以 PyYAML 读取 `jobs.release.steps[-1].run`，原样交给 `bash -c`，仅在 PATH 前置临时 mock `gh`，以记录每次调用并模拟 API 状态。未请求真实 API，未创建真实 Release。

| 模拟 API 响应 | 实际退出码 | 实际 gh 调用 |
| --- | --- | --- |
| 同 tag Release 已存在，含 SHA256SUMS 资产 | 1 | 仅一次 `api repos/local/mock/releases/tags/v1.0.0` |
| 同 tag Release 已存在，assets 为空 | 1 | 仅一次 API 查询 |
| 查询失败 HTTP 403 | 1 | 仅一次 API 查询 |
| 查询明确 HTTP 404 | 0 | API 查询、一次 create、按固定顺序五次 upload |

前三种情况均断言 `returncode != 0` 且总调用数为 1，证明保护真正失败退出，未运行 create/upload；输出包括 `Release or assets already exist; refusing retransmission`。404 分支断言总调用数为 7，最后一次为 `release upload v1.0.0 assets/SHA256SUMS`。原始记录：`target/m4-10/retransmission.log`。

实际创建同名 Release 时，`gh release create` 自身的失败也会被 `set -e` 传播；上传没有 `--clobber`，不覆盖、不删除。concurrency 按 ref 串行化本 workflow 的发布。
