# T16.74 报告：nftset 单点 IPv4 最大地址（255.255.255.255）区间语义核实（M18）

- **工作树**：`/workspace/openwrt/aether-dns-wt/T16.74`
- **分支**：`fix/t16.74-nft-max-ip`
- **基线**：`bf5939dd`
- **修改文件**：`src/nftset.rs`（仅 `#[cfg(test)]` 单元测试，**生产代码零改动**）、`tests/nftset.rs`、`reports/T16.74.md`

## 1. 结论

**现有生产编码正确，无需修改生产代码。**

在 `src/nftset.rs` 的 `body()` 中，写入单点 IPv4 interval 时对每个地址发出 `(key, end=false)` 与 `(key.wrapping_add(1), end=true)`。当地址为 `255.255.255.255`（`0xffff_ffff`）时，右端点确会回绕为 `(0.0.0.0, NFT_SET_ELEM_INTERVAL_END)`。

经隔离 `unshare -Urn` 内核实测（Linux `6.18.58.1-microsoft-standard-WSL2`，`nftables v1.1.6`，后端 `nft_set_rbtree_type`）证实：

1. **符合内核 rbtree 区间表示约定**：`nft --debug=netlink` 显示，`nft` 自身对包含 `255.255.255.255` 的区间（如 `{ 255.255.255.255 }`、`{ 255.255.255.0/24 }`）在 `nft_set_rbtree` 中存储为开放式起点（`ffffffff : 0` 或 `00ffffff : 0`）与零键结束哨兵 `00000000 : 1 [end]`。
2. **不报 `EINVAL` / 误报 `EEXIST`，不误收 `0.0.0.0` 或相邻地址**：`add_batch` 使用 `NLM_F_REQUEST | NLM_F_ACK | NLM_F_CREATE`（未设 `NLM_F_EXCL`），无论目标集合为空、非空、未开启 `auto-merge`，还是已包含 `0.0.0.0` / `0.0.0.0/24`，写入 `255.255.255.255` 均返回 `Ok(())`，且 `NftSet::contains` 与 `nft list set` 均严格只命中目标成员，从不误收 `0.0.0.0`、`0.0.0.1`、`128.0.0.0` 或 `255.255.255.254`。
3. **不破坏批量写入、成员查询与 `EEXIST` 重试契约**：最大地址与普通地址混批（两种顺序）在单次原子批次中全部成功；当集合已存在 `255.255.255.0/24` 时，`add_batch` 仍返回 `EEXIST` 并回滚同批普通地址，`add` 仍按“先查后写 + `EEXIST` 最多重试一次”跳过已有成员并写入缺失地址。

## 2. 编码层断言与真实内核实测区分

### 2.1 编码层断言（离线，无特权）

在 `src/nftset.rs` 的 `#[cfg(test)]` 中新增 `interval_encoding_for_max_prev_mixed_and_normal_batches`，直接解码 `body()` 输出的 netlink 属性：

- `255.255.255.255`（`intervals = true`）编码为 `[(255.255.255.255, end=false), (0.0.0.0, end=true)]`。
- `255.255.255.255` 查询路径（`intervals = false`）仅编码 `[(255.255.255.255, end=false)]`。
- `255.255.255.254`（`intervals = true`）编码为 `[(255.255.255.254, end=false), (255.255.255.255, end=true)]`，不回绕。
- 混合批次 `[255.255.255.255, 192.0.2.10]` 保持单批次编码，未拆分成逐个写入。
- 普通批次 `[192.0.2.1, 192.0.2.2]` 编码为半开区间对 `[192.0.2.1, 192.0.2.2)` 与 `[192.0.2.2, 192.0.2.3)`。

### 2.2 真实内核实测（隔离临时 `unshare -Urn` netns）

在 `tests/nftset.rs` 中新增 `max_ipv4_interval_kernel_scenarios`（受 `NFT_TEST=1` 门控，默认离线单测自动 `SKIP`；通过 `tests/nftset_acceptance.sh` 在隔离 `unshare -Urn` 中执行，不接触宿主默认 netns 或设备），覆盖全部验收场景：

1. **最大地址单独写入**：
   - 空集合（`flags interval; auto-merge;`）：写入 `255.255.255.255` 成功；命中 `255.255.255.255`，未命中 `0.0.0.0`、`0.0.0.1`、`128.0.0.0`、`255.255.255.254`；重复 `add_batch([255.255.255.255])` 返回 `Ok(())`；随后再写入 `0.0.0.0` 两者共存，未命中 `0.0.0.1`、`255.255.255.254`。
   - 非空集合（已有 `1.2.3.0/24`）、已含 `0.0.0.0` 的集合、以及无 `auto-merge` 的 interval 集合：写入 `255.255.255.255` 均成功且仅命中预期成员（额外手工探针亦确认 `0.0.0.0/24` 共存及 `nft delete element ... { 255.255.255.255 }` 正常保留 `0.0.0.0`）。
2. **最大地址与普通地址同批写入**：
   - `[255.255.255.255, 192.0.2.10]` 与 `[192.0.2.10, 255.255.255.255]` 均单批成功；命中 `1.2.3.77`、`192.0.2.10`、`255.255.255.255`，未命中 `0.0.0.0`、`0.0.0.1`、`192.0.2.9`、`192.0.2.11`、`255.255.255.254`。
   - `[255.255.255.255, 0.0.0.0]` 同批写入亦仅命中 `0.0.0.0` 与 `255.255.255.255`，未命中 `0.0.0.1`、`128.0.0.0`、`255.255.255.254`。
3. **最大值前一个地址（`255.255.255.254`）**：
   - 单独写入仅命中 `255.255.255.254`，未命中 `0.0.0.0`、`255.255.255.253`、`255.255.255.255`。
   - 与 `255.255.255.255` 同批写入命中两者，未命中 `0.0.0.0`、`0.0.0.1`、`255.255.255.253`。
4. **普通批次与重叠回滚**：
   - `[192.0.2.10, 192.0.2.20, 192.0.2.30]` 仅命中三者，未命中其各自左右邻址、`0.0.0.0` 与 `255.255.255.255`。
   - 集合已含 `255.255.255.0/24` 时，`add_batch([198.51.100.1, 255.255.255.255])` 返回 `EEXIST` 并回滚 `198.51.100.1`；`add([255.255.255.255, 198.51.100.1])` 跳过已有最大地址并成功写入 `198.51.100.1`。
