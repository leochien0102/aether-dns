# T1.3 完成报告

- **单一目标**：提供“解析检查 + 原始字节原地修改”的工具层，转发路径不重编码。
- **验收**
  1. `cargo test --test dns_wire` 退出 0；输出覆盖语料数 ≥12。
  2. `cut_additional` 对每个样本的偏移与期望一致（含 `resp-A+OPT` 的 `len-11`）。
  3. raw-forward 断言：响应字节与输入仅 ID/RA/AR 不同。
  4. 报告中列出与 chinadns-ng 的已知边界差异。

## 改动
- `Cargo.toml`、`Cargo.lock`：按任务要求引入并锁定 hickory-proto 0.25.2；用户明确批准此两文件的改动。

## 偏差与待定
- 本卡只提供工具，未实现监听或实际转发；宽松检查独立于 hickory 完整报文解析。压缩指针扫描只跳过编码、不验证指针目标，与语义解析的接受面不同。
- M0 已知边界：多 question、零 question、畸形 label、短包时 chinadns-ng 返回坏响应，本工具只报告检查错误，未规定调用方如何回复；异常压缩指针可能被 hickory 拒绝但 chinadns-ng 转发。尾部垃圾由原始字节保留，截断操作按调用者决定执行。
- 代码无 TODO(design)。`IMPROVEMENTS.md` 条目文字仍标 pending，但 `docs/tasks/README.md` D1 与 `PLAN.md` 记录批准。

## 复审修正
- `check_query` 拒绝 QR=1、qdcount 非 1、qname wire 长度不在 1..255 及不可读 question；不以 opcode/qclass/尾部垃圾作门禁。
- `synthetic_nodata` 仅设置 QR/RA、清 rcode 与 AN/NS/AR，保留 opcode/AA/TC/RD/Z/AD/CD。
- 真实语料迁至 `tests/data/wire/real-samples.json`；测试不再引用 spikes，查询通过门禁、响应拒绝。
- 新增 QR/双 question/短包/256 字节 qname 负例及 255 字节边界正例；新增所有待保留标志非零的精确断言。
