## 重试策略与资源清理

### 子进程 harness

1. 总尝试次数上限为 10（含首次；预留阶段竞争也计入），每轮预留所有地址、所有端口的 TCP 和 UDP；已尝试的端口不再使用。
2. 释放预留后写本轮独立 conf 并启动二进制。conf 路径由 PID 和进程内原子序号组成，避免多个测试覆盖同一配置文件。
3. 通过独立线程逐行读取并持续排空 stderr，按服务端顺序逐一核对所有预期 `listening UDP ...` / `listening TCP ...` 行。
4. 任何非预期行（包括 `Address already in use` 等绑定诊断）、提前 EOF、等待超时，或读齐就绪行时进程已退出，均使当前端口失败；不会把错误行当成就绪。
5. 每次失败先 drop RAII guard：`kill` + `wait` + 删除 conf，再 join stderr 读取线程，之后才开始下一轮；spawn 失败也先删除 conf 再报错。
6. 成功后的查询不重试、不放宽断言；最终 drop 同样执行 `kill` + `wait` + 删除 conf。成功路径的 stderr 持续排空，不会因无人读取而阻塞被测进程。

### 进程内 harness

- `tc_clear` 原本不是子进程。保持原有注入式 `run_with_ip_test` 和 `NoIpTest`，不将测试改为另一种生产调用语义。
- 同样最多 10 轮，预留双协议、每轮换端口。启动任务退出即判本轮失败并收集错误；失败任务被 await 回收。2 秒就绪等待到期时先 abort + await，再重试。
- 保留 TCP 就绪探测；用调度让出和任务完成检查替代原来的 5 ms sleep，优先观察启动任务退出，避免将竞争进程的 TCP 响应误认为本服务就绪。
- 进程内启动不生成临时 conf，也不生成子进程；成功后仍用原来的 watch shutdown 并 await 服务任务。
- 未新增 sleep；保留其他既有业务时序 sleep（例如 timeout 测试的分段发送，以及 routing 的既有计数观察窗口）。
