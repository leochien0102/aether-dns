## 1. 随机来源与失败语义

- **系统随机源**：新增 `UpstreamIdSource` 抽象与生产实现 `OsRandomIdSource`（`src/server.rs`），直接复用已锁定依赖 `libc = "0.2"` 调用 Linux 内核 CSPRNG 系统调用 `libc::getrandom(buf, len, 0)` 读取 2 字节生成 16 位事务 ID（未新增依赖，未改动 `Cargo.toml` / `Cargo.lock`）。
- **不自造 PRNG、不降级**：
  - 对 `EINTR` 重试并处理部分读取；遇到其他系统错误或返回 0 字节时直接向上返回 `io::Error`，绝不降级到计数器、时间戳或 `client_id + 1` 等可预测值。
  - `select_upstream_id(source, avoid_id)` 在生成值与客户端 ID 碰撞时从随机源重新抽取（保留均匀分布且满足与客户端 ID 不同的约束）；设置有限重试上限（16 次），若持续碰撞则 fail-closed 返回错误，不回退到可预测值。
  - 发生分配错误时，客户端 UDP/TCP 查询在 `handle_query` 中以原始 `client_id` 返回 `SERVFAIL` 且不向外发送任何上游报文；后台刷新将 `None` 交给 `finish_refresh` 进入冷却。

## 2. 实际发送路径审阅与调用点

全仓所有上游 DNS 发送最终均经 `upstream_group::exchange_with_limit` → `upstream::exchange` 发出，由 `server::exchange_response` 统一调度。本次改造：

1. **移除监听器顺序计数器**：删除 `run_inner` 中 UDP 监听器与 TCP 监听器的 `next_id` 局部变量及递增逻辑，同时移除 `tcp_query` / `handle_query` 的 `id` 透传参数。
2. **统一在 `server::exchange_response` 分配上游 ID**：
   - 每个新的逻辑上游查询进入 `exchange_response` 时，先完成路由解析，再调用 `select_upstream_id(&*upstream.id_source, avoid_id)` 分配新的不可预测 16 位 ID，并克隆报文写入该 ID 后再下发：
     - **UDP 缓存未命中路径**：`handle_query` → `forward` → `exchange_response(..., Some(client_id), Protocol::Udp)`。
     - **TCP 缓存未命中路径**：`tcp_query` → `handle_query` → `forward` → `exchange_response(..., Some(client_id), Protocol::Tcp)`。
     - **后台刷新路径**：`forward` 在缓存命中且 `begin_refresh` 成功时派生刷新任务，在任务内调用 `exchange_response(&routing, &query, Some(client_id), client_protocol)`，为每次刷新独立分配新的不可预测 ID，不复用监听器计数器、客户端 ID 或历史缓存报文 ID。
     - **同一逻辑查询的并行尝试**：单组多上游（`upstream_group::exchange_with_limit`）与 `none` 双组并发（`none_exchange` 中的 `china_dns` / `trust_dns`）共用本次 `exchange_response` 分配的同一 ID，不建全局 ID 表。
     - **测试辅助入口**：`exchange_once_with_limit` 同样经 `exchange_response` 走 `OsRandomIdSource` 分配。
3. **非上游路径与客户端 ID 恢复**：
   - `no_ipv6` / `filter_qtype` 过滤直接返回合成 NODATA（保持原 `client_id`），不消耗随机源。
   - 缓存命中且无需后台刷新时，直接按本次 `client_id` 恢复回包并返回，不发起上游查询也不消耗随机源。
   - 缓存未命中与缓存命中回包均通过 `dns::set_id(&mut response, client_id)` 恢复本次客户端 ID；上游失败时使用保留原始 `client_id` 的 `original` 构造 `SERVFAIL`。
4. **测试注入点**：新增 `server::run_with_id_source` 供确定性集成测试注入脚本化/故障 `UpstreamIdSource`，既有 `run` 及所有 `run_with_*` 入口均默认使用 `OsRandomIdSource`，保持签名与行为兼容。

## 3. 验证结果

1. **专项测试**：

     - `select_upstream_id_uses_source_and_redraws_on_collision`：核实使用源值及连续碰撞客户端 ID 时重抽。
     - `select_upstream_id_fails_closed_on_source_error_and_stuck_collision`：核实随机源报错与持续碰撞 16 次均 fail-closed。
