## 1. 设计与实现

1. **复用已有 wire 解析设施实现单问题核对（`src/dns/mod.rs`）**
   - 沿用 `src/dns/mod.rs` 既有的 wire 解析风格与 `word` / `WireError`，新增 `NameCursor` 与 `dns::same_question(response, query) -> bool`：
     - 从报文偏移 `12` 开始按 DNS 名称标签逐段读取并比较 `response` 与 `query` 的第一个 Question：
       - **QNAME**：逐标签比对长度与内容，使用 `eq_ignore_ascii_case` 实现**仅忽略 ASCII 大小写**的等价比较；保留标签边界语义（如 `a.bc` 与 `ab.c` 不等价），非 ASCII 字节（如 UTF-8 `É` 与 `é`）严格按字节比对。
       - **QTYPE / QCLASS**：在 QNAME 结束后精确读取并比较 16 位 `QTYPE` 与 `QCLASS`。
       - **安全与边界约束**：无 panic，将首个 Question 的 QNAME 严格限定为普通 DNS 标签（`1..=63`）与根终止符（`0`），不引入压缩指针跟随状态，直接拒绝任何压缩指针（`0xc0..=0xff`，含指向先前标签数据内部的后向指针）、`< 12` 字节短报文、标签越界、缺失根标签 `0`、截断的 QTYPE/QCLASS、非法标签类型位（`0x40..=0xbf`）及超长名称（> 255 字节）；不改通用 RR 解析器，正常应答的 Answer 区段压缩指针不受影响。
       - **合法 `TC=1` 兼容**：仅解析至第一个 Question 末尾，不解析 Answer/Authority/Additional 区段，因此问题完整且匹配的合法 `TC=1` 应答不会因尾部截断而被拒绝。
2. **UDP/TCP 共用校验点保留既有标头约束与传输语义（`src/upstream.rs`）**
   - 在 `upstream::valid_reply(response, query)` 中保留原有 `response.len() >= 12`、ID 匹配、`QR=1`、`QDCOUNT=1` 检查，同时校验 `query.len() >= 12` 与 `query[4..6] == [0, 1]`，并追加 `dns::same_question(response, query)`。
   - **UDP 语义不变**：`Protocol::Udp` 仍在同一 5 秒 `tokio::time::timeout` 总预算循环内忽略未通过 `valid_reply` 的报文，继续等待匹配应答或超时。
   - **TCP 语义不变**：`Protocol::Tcp` 在读取完整帧后经同一 `valid_reply` 校验，不匹配时直接返回 `io::ErrorKind::InvalidData`。
   - 未修改上游 ID 生成、客户端回包、缓存/名单键、选路逻辑或并发额度。
