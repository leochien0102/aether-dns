## server.zig 判定依据

只读来源：`/tmp/src/chinadns-ng-2025.08.09/src/server.zig`，`use_china_reply` 从 637 行开始，`on_reply` 从 657 行开始。

```zig
return switch (test_res) {
    .is_china_ip, .non_china_ip => b: {
        const accepted = test_res == .is_china_ip;
        verdict_cache.add(msg, qnamelen, accepted);
        break :b accepted;
    },
    .no_ip_found => b: {
        if (g.verbose()) rlog.china_noip();
        break :b g.flags.noip_as_chnip;
    },
    .other_case => dns.is_tc(msg), // allow truncate
};
```

`on_reply` 的 none + A/AAAA 分支：

- china 命中 `use_china_reply` 则采用 china，丢弃之前暂存的 trust。
- china 不命中时，有 `q.trust_msg` 就采用它，否则标记当前查询 non-china 并等待 trust。
- trust 在 china 判定前到达时，仅把首个响应保存在 `q.trust_msg`；china 判为 non-china 后可直接采用 trust。
- 不属于 none + A/AAAA 的响应直接接受，不做这项 IP 测试。

为理解 `other_case`，另只读了该源码 `src/dns.c:415–467`：`dns_test_ip` 对非 good 响应返回 OTHER_CASE，遍历 answer 时遇到首个 A/AAAA 就停止。故 **TC=0 并不否决已命中的 china IP**；无 IP/不命中/other_case 且 TC=0 才走 trust，TC=1 接受 china。这里不实现 `noip_as_chnip`。

本卡按任务卡明确要求处理空组和单侧失败：一组空时直接使用另一组；一侧失败/超时不掩盖另一侧合法响应，包括 trust 失败但 china 合法的情形；两侧均无合法响应才 SERVFAIL。

已阅读 M0 `spikes/m0-fixtures/baseline.json` 的相关场景：

- `t14-bypass-cn-t1`：none-china / none-noncn 均命中 china 1/2 和 trust 11/12；分别采用 10.0.0.1 / 10.0.0.11；none 不写 gfw4。
- `t922-mixed` / `t922-explicit-tcp`：china/trust 多端点及 UDP/TCP 混合，采用 10.0.0.1；本卡沿用现有组交换和协议选择。
- `t923-wan-t3`：china 4/5/3 端点，采用 10.0.0.4；不需要 trust 才能返回。
- baseline 中 AAAA/filter-qtype 和 nftset 写入属于后续卡；本卡不实现它们。
