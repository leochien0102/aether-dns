## 1. 设计与实现

1. **按单个上游交换尝试计数，单实例全路径共享同一额度（`src/upstream_group.rs`、`src/server.rs`）**
   - 在 `src/upstream_group.rs` 新增 `UpstreamLimiter`（内部持有共享 `Arc<tokio::sync::Semaphore>` 与可选测试观测通道 `watch::Sender<UpstreamAdmissionStats>`）及 `exchange_with_limit`，保留原有 `exchange` 签名供既有单元测试复用。
   - 在 `src/server.rs` 的 `Routing` 中持有唯一的 `upstream_limiter`，通过 `Arc<Routing>` 共享给全部客户端 UDP 监听任务、客户端 TCP 连接任务、双组 `none_exchange`（含非 A/AAAA 合并组、verdict 命中单侧、单侧空配置与双侧并发）以及后台缓存刷新任务（`refresh_tasks`）；全部 7 处 `upstream_group::exchange` 调用均切换为 `upstream_group::exchange_with_limit`，确保任意入口均无法绕过同一额度池。
   - 保留既有 `run` / `run_with_ip_test` / `run_with_ip_writer` / `run_with_cache_clock` / `run_with_tcp_limit` / `run_with_limits` 签名与行为，新增 `run_with_upstream_limit` 与 `run_with_all_limits` 供测试注入小额度与观测通道；不新增依赖与配置项。
2. **生产默认值与取舍：`DEFAULT_MAX_UPSTREAM_ATTEMPTS = 256`**
   - **选择理由**：面向 OpenWrt 家庭/SOHO 路由器（常见 128–512 MiB 内存、默认 `ulimit -n = 1024`），单次上游交换在 `src/upstream.rs` 内持有 1 个上游 socket/连接及 1 块 64 KiB 接收缓冲；在客户端侧已允许最多 256 路 UDP + 128 路 TCP 并发且多上游/双组查询单次可扇出 2–4+ 路尝试的前提下，将同时在途的单上游交换上限设为 256：
     - 将上游尝试接收缓冲上界控制在 ~16 MiB，上游 socket 数远低于典型 `RLIMIT_NOFILE`（1024），为客户端 TCP 连接、监听 socket 与运行时留足余量，同时为常见多上游组与双组查询留出并发余量。
   - **明确边界**：该额度仅约束单个服务实例同时在途的上游交换尝试数，**不声称已限制全进程 FD 或 RSS 上限**（缓存、verdict、客户端缓冲及运行时仍各自占用资源）。
3. **资源分配前取额度、部分满额不掩盖已接纳答案与真实错误、全路径释放与有界失败**
   - 在 `upstream_group::exchange_inner` 中，对组内每个上游在构造 `Box::pin(upstream::exchange(...))`（即在 `UdpSocket::bind` / `TcpStream::connect` 与 64 KiB 缓冲分配）**之前**调用 `limiter.try_acquire()`：
     - **满额被拒**：直接记录该槽位为 `io::ErrorKind::WouldBlock`，不创建上游 future、不分配 socket/缓冲、不派生等待任务、不排队、不逐次刷日志。
     - **部分接纳**：已接纳的尝试继续竞争，正常 `NOERROR`/`NXDOMAIN` 与既有 DNS 错误回退（`SERVFAIL`/`REFUSED`/扩展 RCODE）优先级保持不变，不会被同组或另一侧的满额拒接掩盖。
     - **双组结果合并（`merge_dual_results`）**：在 `none_exchange` 中，当 `china` 未通过 `use_china_reply` 胜出且两侧均返回错误时，若一侧因满额被拒（`WouldBlock`）未发出请求、另一侧实际交换后发生 I/O 错误，无论 `china`/`trust` 位置与完成顺序均保留实际交换错误（使其可观测并走常规错误日志路径）；仅当两侧均因满额被拒时返回 `WouldBlock` 并静默返回合成 `SERVFAIL`。已有成功应答、DNS 错误应答与路由选择顺序保持不变。
     - **全部无法接纳**：立即返回 `io::ErrorKind::WouldBlock`。`handle_query` 对该类满额错误跳过逐次 `println!` 刷日志，直接返回合成 `SERVFAIL`（保留原报文 ID）；`forward` 在 `exchange_response(...).await?` 处提前返回，**不写入缓存**；后台刷新进入 `finish_refresh(&query, None, now)` 释放刷新占位并触发既有 5 s 冷却，不破坏既有缓存条目。
   - 每个已接纳条目在 `pending` 中以 `(index, future, permit)` 顺序存放，确保无论正常完成、I/O 错误、5 s 超时、同组/双组竞争取消还是 500 ms 关停预算到期中止，Drop 时先释放上游 socket/流与缓冲，再归还信号量额度并更新观测计数。
   - 保持既有客户端 UDP/TCP 接纳策略、协议选择、组内 RCODE 优先级、完整 TCP 报文、缓存语义与 500 ms 全局关停预算。

## 2. 观察点、生产值与测试值

- **生产默认值**：`DEFAULT_MAX_UPSTREAM_ATTEMPTS = 256`（UDP 保持 `DEFAULT_MAX_UDP_QUERIES = 256`，TCP 保持 `DEFAULT_MAX_TCP_CONNECTIONS = 128`）。
- **测试配置值与同步屏障**：
  - 跨组/跨请求/UDP+TCP/双组共享测试：`max_upstream_attempts = 2`，`Tag::None` 配 `2 china_dns + 2 trust_dns` 共 4 个受控本机 UDP 上游（`mpsc::UnboundedReceiver` 屏障 + 原子命中计数）。
  - 组内部分接纳与错误/回退路径测试：`UpstreamLimiter::new(1, ...)` 配 2 个受控上游（UDP + 立即关闭的 TCP 监听器）。
  - 取消释放与满额关停收敛测试：直接 drop 取消使用额度 `1`；服务端满额关停使用额度 `2` 配 2 个静默受控上游。
  - 后台刷新共享额度测试：`max_upstream_attempts = 1`，`cache = 32`、`cache_stale = 30`、`FakeClock` 配 1 个受控 UDP 上游。
- **双重观测**：通过 `watch::Sender<UpstreamAdmissionStats>`（生产路径为 `None`）观测 `admitted`、`active`、`peak_active`、`rejected`，并结合受控上游实际收包计数 `hits`，证明被拒尝试从未抵达上游。

## 3. 验证结果

1. **专项测试**：`cargo test --locked --offline --test upstream_admission -- --nocapture`
   - **11 passed, 0 failed, 0 ignored**（耗时 0.51s）
   - 关键实测记录：
     - `default_upstream_limit_is_bounded_and_independent`：确认 `DEFAULT_MAX_UPSTREAM_ATTEMPTS == 256`、`DEFAULT_MAX_UDP_QUERIES == 256`、`DEFAULT_MAX_TCP_CONNECTIONS == 128`。
     - `shared_quota_across_groups_udp_tcp_and_dual_exchange`：
       - `shared_upstream_quota: test_limit=2 prod_limit=256 admitted=4 peak_active=2 rejected=12 upstream_hits=4`
       - 验证 4 上游双组查询在额度 2 下仅接纳 2 路、拒接 2 路（上游仅收到 2 包）；满额期间新增 TCP 与 UDP 查询均即时返回 `SERVFAIL` 且不抵达上游、峰值不越限（`peak_active == 2`）；放行 1 路已接纳尝试后原查询仍正常返回 `NOERROR` 且取消另一路并归还全部额度（`active == 0`）；随后重发此前被拒的 TCP 查询顺利抵达上游并返回完整 TCP `NOERROR`（证明 `SERVFAIL` 未被缓存）。
     - `partial_admission_preserves_admitted_success_fallback_and_releases_on_error`：
       - 验证额度 1、双上游组下：已接纳上游返回 `NOERROR` 或 `REFUSED` 时不被满额拒接掩盖，被拒上游命中为 0；已接纳 TCP 上游断开报错时返回 I/O 错误（非 `WouldBlock`）并归还额度，后续查询立即成功。
     - `dual_merge_preserves_actual_exchange_error_regardless_of_side`：
       - 确定性构造额度 1 与双侧受控 TCP 监听器，分别覆盖 `china` 被拒 / `trust` 已接纳且 TCP EOF 失败、以及 `trust` 被拒 / `china` 已接纳且 TCP EOF 失败；断言合并结果保留真实 I/O 错误（非 `WouldBlock` 且包含已接纳上游地址）、被拒侧无连接、额度归还（`active == 0`）；同时验证两侧均被拒时仍返回 `WouldBlock`。
     - `none_exchange_preserves_actual_io_error_when_other_side_rejected`：
