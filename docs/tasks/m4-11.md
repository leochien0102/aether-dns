## M4-11 生命周期日志改用 stdout（**冻结 2026-11-13**）

- **单一目标**：把生命周期/信息类日志从 stderr 改到 stdout，使固件 syslog 不再把它们记成 `daemon.err`；消息文本一字不改。
- **分支**：`fix/log-stream-priority`
- **卡片版本**：以本卡冻结提交为准（见发卡入口提示）；本卡不记录自身提交号

> 所有者 2026-11-13 直接下达并要求由设计负责人一并实现，故本卡不走"转发实现者"流程。

## 背景与证据（真机）

H28K（aether-proxy 1.1.2-r1 + aether-dns 1.0.0-r1）的 syslog 里出现正常生命周期被记成错误：

```text
Fri Nov 13 09:10:48 daemon.err aether-proxy[19530]: listening TCP 127.0.0.1:37357
Fri Nov 13 09:10:48 daemon.err aether-proxy[19530]: listening UDP 127.0.0.1:37357
Fri Nov 13 09:10:48 daemon.err aether-proxy[19530]: shutdown: draining queries (500 ms maximum)
```

机制：aether-dns 用 `eprintln!` 写这些行；子进程继承 aether-proxy 的 stderr，**procd 把子进程 stderr 记为 `daemon.err`、stdout 记为 `daemon.info`**。对照：Xray 写 stdout 所以是 info。

代理侧不解析这些行（`aether-proxy/src/lib/monitor.uc` 用 `net.tcp_listening()` 探端口），但 `docs/09` 会按**文本**分类日志，所以文本必须保持不变。

## 允许改动

- `src/server.rs`（仅日志宏与那行协议注释）
- `tests/common/mod.rs`、`tests/lifecycle.rs`、`tests/tcp_timeout.rs`、`tests/upstream_log.rs`、`tests/fake_upstream.py`
- 新增 `tests/log_streams.rs`
- `README.md`（新增"日志流约定"一节）
- `reports/M4-11.md`

不改 `src/` 其它文件、`Cargo.toml`/`Cargo.lock`、`openwrt/`、`.github/`、版本号、其他仓库。

## 做什么（分类已冻结）

| 位置 | 文本 | 分类 | 目标流 |
|---|---|---|---|
| `server.rs:143` | `listening UDP {addr}` | 生命周期 | **stdout** |
| `server.rs:190` | `listening TCP {addr}` | 生命周期 | **stdout** |
| `server.rs:228` | `shutdown: draining queries (500 ms maximum)` | 生命周期 | **stdout** |
| `server.rs:302` | `upstream failed for client {peer}: {error}` | 可恢复的诊断（上游超时/重置，已回 SERVFAIL） | **stdout** |
| `server.rs:160` | `UDP receive: {error}` | 真实错误 | stderr（不变） |
| `server.rs:206` | `TCP accept: {error}` | 真实错误 | stderr（不变） |
| `server.rs:216` | `TCP client {peer}: {error}` | 真实错误 | stderr（不变） |
| `server.rs:460` | `UDP send {peer}: {error}` | 真实错误 | stderr（不变） |
| `ip_writer.rs:81` | nftset 写入失败 | 真实错误 | stderr（不变） |
| `ip_test.rs:50` | IP 测试失败、按非 china 处理 | 真实错误 | stderr（不变） |
| `main.rs:53` | 配置/启动错误 | 真实错误 | stderr（不变） |
| `main.rs:59` | 用法错误（exit 2） | 真实错误 | stderr（不变） |

1. 上述四行只把 `eprintln!` 改成 `println!`，**参数字面量与格式串一字不动**。
2. `server.rs:224` 的注释"Keep the M1 stderr readiness/shutdown protocol unchanged"改为说明新协议：就绪/收尾走 stdout，错误走 stderr。
3. 测试 harness 改为**同时捕获两个流**：
   - `tests/common/mod.rs`：`info`（stdout）用于就绪与生命周期断言，`errors`（stderr）保留诊断；两个流都必须持续 drain，避免管道写满阻塞子进程。
   - `tests/lifecycle.rs`：同上（`listening`/`shutdown` 从 stdout 读）。
   - `tests/tcp_timeout.rs`、`tests/upstream_log.rs`：改读 `info`。
   - `tests/fake_upstream.py`：把 stdout 写进就绪日志（原来写的是 stderr），stderr 另存为诊断文件；`Address already in use` 的识别改到 stderr 文件。
4. 新增 `tests/log_streams.rs`：起真实子进程，断言
   - 启动后 stdout 依次出现两条 `listening`，**stderr 为空**；
   - 查询打到已关闭的上游后，`upstream failed for client …` 出现在 **stdout**，stderr 仍为空；
   - 用不存在的 `-C` 配置文件启动，**stderr** 有错误且 stdout 为空（证明真实错误仍在 stderr）。
5. `README.md` 增一节"日志流约定"：stdout=info、stderr=err，并写明 procd 的 err/info 映射与"文本不得随意改"的理由。

## 不做什么

- 不改任何消息文本、前缀、时间戳、字段顺序。
- 不改监听地址/端口、drain 预算、退出码、信号语义、协议行为。
- 不改 aether-proxy、固件、syslog 配置、版本号。
- 不为"看起来更整齐"重排日志顺序。

## 停点

- 若发现某个既有测试必须**放宽断言**才能通过 → 停下汇报（说明分类有误或改动超出范围）。
- 若发现 proxy 侧确实解析 aether-dns 的 stderr 就绪行（而不是探端口）→ 停下，先跨项目确认。
- 若发现 `-V`/usage 等 CLI 输出的流被牵连 → 停下（只改生命周期四点）。

## 验收（命令 + 可判定结果）

1. `cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test --all`、`bash tests/review.sh`（FAIL=0）。
2. `cargo test --test log_streams` 全过，且三条断言分别覆盖：就绪在 stdout、上游诊断在 stdout、配置错误在 stderr。
3. 手动：直接跑二进制并分离两个流，`stdout` 只有生命周期/信息、`stderr` 为空；再用坏配置跑一次，`stderr` 只有错误、`stdout` 为空。报告贴命令与输出。
4. 文本未变：`git diff main...HEAD -- src/` 中四行的字符串部分无变化，报告贴 diff 并逐行说明只改了宏。
5. `git diff --stat main...HEAD` 只含「允许改动」。
