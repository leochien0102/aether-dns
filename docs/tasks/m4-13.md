## M4-13 发布 1.0.2：版本单一口径 + 裸二进制资产 + 回退本地打包（**冻结 2026-11-14**）

- **单一目标**：让包版本、Cargo 版本与 `-V` 三者同为 `1.0.2`（包 `1.0.2-r1`），并在 Release 中增加两个无扩展名裸二进制，使 feeds 打包可以移到 aether-proxy 仓库后直接下载。
- **分支**：`release/1.0.2`
- **卡片版本**：以本卡冻结提交为准（见发卡入口提示）；本卡不记录自身提交号

> 依据：aether-proxy `docs/design/versioning-20261114.md` §2 R1/R2/R3、§6 T3/T4（只读引用）。
> 分工：实现者做代码与本地验证并交回；**推分支、触发 CI、合并、打 tag、发 Release 由设计负责人执行**。

## 背景与证据

现状（2026-11-14，main `c1fd5b9`）：

| 对象 | 当前值 | 问题 |
|---|---|---|
| `Cargo.toml` / `Cargo.lock` | `1.0.0` | 与包版本脱节 |
| `openwrt/Makefile` `PKG_VERSION` / `PKG_RELEASE` | `1.0.1` / `1` | 包是 `1.0.1-r1` |
| 二进制 `-V` | `aether-dns 1.0.0`（由 Cargo 派生） | 组件页与实际安装版本不一致 |
| Release | `v1.0.0`、`v1.0.1` 各 4 包 + `SHA256SUMS` | 没有 feeds 可直接下载的裸二进制 |

下游变化（proxy 侧同日的决定）：feeds 的打包将移到 aether-proxy 仓库的 `aether-dns/Makefile`（chinadns-ng 模式），
**直接下载本仓库 Release 里的无扩展名裸二进制**，DNS 仓库不再承担 feeds 打包。

`openwrt/Makefile` 现有"无本地文件则下载 ipk"的分支（`LOCAL_BINARY` 为空时用 `PKG_SOURCE`/`PKG_SOURCE_URL`/`PKG_HASH`），
其中 `ifeq ($(ARCH),aarch64_generic)` 是错的：**OpenWrt 的 `ARCH` 是 `aarch64`/`x86_64`**，不是包架构记号。
删除该分支后这个错误自然消失。

## 允许改动

- `Cargo.toml`、`Cargo.lock`（仅 aether-dns 自身版本）
- `tests/cli.rs`（版本断言的目标值）
- `openwrt/Makefile`、`openwrt/README.md`
- `.github/workflows/release.yml`
- `tests/ci/verify-assets.sh`
- 新增 `tests/ci/check-version.sh`
- `README.md`、`docs/handoffs/session-handoff-20261109.md`
- `reports/M4-13.md`

不改 `src/`（除版本派生本来就没有硬编码）、不改 proxy/channel/固件、不改 `.github/` 之外的 CI、不加 remote、不推 tag。

## 做什么

### 1. 版本单一口径（R1/R2）

1. `Cargo.toml`：`version = "1.0.2"`；`Cargo.lock` 里 `name = "aether-dns"` 那条同步 `1.0.2`（依赖条目不动）。
2. `openwrt/Makefile`：`PKG_VERSION:=1.0.2`、`PKG_RELEASE:=1` → 包版本 `1.0.2-r1`。
3. `tests/cli.rs`：把"迁移目标 `1.0.0`"的断言改为 `1.0.2`；保留"banner 第二字段 == `CARGO_PKG_VERSION`"这条派生断言。
4. `-V` 输出 `aether-dns 1.0.2`（只输出核心，不带 `-r1`）。
   说明：proxy 文档 R2 对第一方组件写的是"应输出完整规范串"，但**所有者 2026-11-14 明确要求 `-V` 输出 `1.0.2`**；
   proxy 侧按 R3 用"已装包版本（规范化 `-rN`）+ 二进制核心比对"判定一致性，因此核心口径即可。报告里要写这条偏离及理由。

### 2. 版本守卫（新增，CI 与本地共用）

新增 `tests/ci/check-version.sh`：

```sh
cargo_ver = Cargo.toml 的 version
pkg_ver   = openwrt/Makefile 的 PKG_VERSION
pkg_rel   = openwrt/Makefile 的 PKG_RELEASE
```

- 三者必须存在且 `cargo_ver == pkg_ver`，否则退出非 0 并打印两个值；
- 可选第 1 个参数是 `-V` 的完整输出（`aether-dns <ver>`），传入时断言 `== "aether-dns $cargo_ver"`；
- 成功时打印 `version ok: <cargo_ver>-r<pkg_rel>`。

接入 CI：
- `binaries` 作业在构建与 `-V` 检查之间调用它（传入实际 `-V` 输出），不一致直接失败；
- `verify` 作业在生成资产前再调用一次（不传 `-V`），防止打包阶段与源码脱节。

### 3. Release 增加两个裸二进制

1. `verify` 作业新增一步：把 `binary-aarch64_generic`、`binary-x86_64` 两个 artifact 复制成

   ```text
   aether-dns-<cargo_ver>-r<pkg_rel>-aarch64_generic
   aether-dns-<cargo_ver>-r<pkg_rel>-x86_64
   ```

   **无扩展名**（与 chinadns-ng 上游一致），`chmod 0755`。
2. 断言：`file` 显示 `statically linked`、`readelf -d` 无 `NEEDED`、`-V` 为 `aether-dns <cargo_ver>`（aarch64 走 `qemu-aarch64-static`）。
3. `SHA256SUMS` 覆盖 **6 个资产**（4 包 + 2 裸二进制）。
4. `release` 作业的上传清单与数量断言从 5 改为 7，顺序固定：

   ```text
   ipk aarch64, ipk x86_64, apk aarch64, apk x86_64, 裸 aarch64, 裸 x86_64, SHA256SUMS
   ```

5. 已知约束（写进 `openwrt/README.md` 与报告）：**GitHub Release 不保留可执行位**，消费方（proxy 的 Makefile）下载后必须 `chmod +x`；CI 内部断言 0755。

### 4. `tests/ci/verify-assets.sh`

- 资产集合从"恰好 4 个包 + SHA256SUMS"改为"**恰好 4 个包 + 2 个裸二进制 + SHA256SUMS**"；
- 裸二进制命名正则：`^aether-dns-([0-9][0-9A-Za-z.+~-]*-r[0-9]+)-(aarch64_generic|x86_64)$`；
- 断言裸二进制为普通文件、非符号链接、**权限含 0755 的可执行位**、大小 > 0；
- 断言 6 个资产的版本串一致（与既有包名解析共用同一版本）；
- `SHA256SUMS` 必须恰好 6 行且 `sha256sum -c` 通过；
- ipk 的 control 校验逻辑不变。

### 5. `openwrt/Makefile` 回退为只打包本地二进制

- 删除 `LOCAL_BINARY` 分支、`PKG_SOURCE` / `PKG_SOURCE_URL` / `PKG_HASH` 与从 ipk 解包的 `Build/Prepare`；
- 只保留一个 `Build/Prepare`：把 `./files/aether-dns` 拷到 `$(PKG_BUILD_DIR)/aether-dns`；
- 文件头注释改写：本目录只服务本仓库 CI 打包；feeds 打包已移到 aether-proxy 仓库的 `aether-dns/Makefile`（下载裸二进制）；
- `openwrt/README.md` 同步：删掉下载分支说明，版本改 `1.0.2`/`1.0.2-r1`，补"Release 不保留可执行位、消费方 chmod"的说明。

### 6. 文档

`README.md` 当前状态、`docs/handoffs/session-handoff-20261109.md` 的版本表（Cargo、`-V`、包版本、Release 资产）更新到 1.0.2；
发布本身（tag/Release）由设计负责人执行并回填。

## 不做什么

- 不改协议、日志流、缓存、路由、监听等任何运行时行为（本卡只有版本与打包管线）。
- 不碰 aether-proxy / channel / 固件；不动 M4-12 的测试改动；不引入 tarball 资产。
- 不推 tag、不建 Release、不 push 到远端。
- 不改 `tests/ci/verify-assets.sh` 之外的 CI 脚本语义（`NO_SHFMT_CHECK`、feed staging、apk 工具获取保持原样）。

## 停点

- 若 `-V` 需要输出 `1.0.2-r1` 才能满足 proxy（与所有者本次指示冲突）→ 停下，由所有者裁决。
- 若 CI 的 artifact 传递丢失可执行位、导致 0755 断言无法成立 → 停下汇报（不要放宽断言）。
- 若需要改 proxy 仓库的 `aether-dns/Makefile` 或 channel 清单 → 停下（跨仓库，另行分工）。
- 若守卫要求改动 `tests/cli.rs` 之外的既有断言 → 停下。

## 验收（命令 + 可判定结果）

1. `cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test --all`、`bash tests/review.sh`（FAIL=0）。
2. `cargo run -- -V` 输出恰为 `aether-dns 1.0.2`。
3. `sh tests/ci/check-version.sh "$(cargo run -q -- -V)"` 通过并打印 `version ok: 1.0.2-r1`。
4. **守卫有效性**：临时把 `Cargo.toml` 改成 `1.0.3`，`sh tests/ci/check-version.sh` 必须退出非 0 并打印不一致的两个值；改回后通过。报告贴命令与输出。
5. 本地 SDK 打包仍可用（用占位二进制）：`make package/aether-dns/compile` 产出 `aether-dns_1.0.2-r1_aarch64_generic.ipk`，control 的 `Version: 1.0.2-r1`；`openwrt/Makefile` 中已无 `PKG_SOURCE`/`PKG_HASH`。
6. `sh tests/ci/verify-assets.sh <目录>`：构造"4 包 + 2 裸 + SHA256SUMS"的合成目录应通过；删掉一个裸二进制或改坏权限应失败（负向用例，报告贴结果）。
7. `git diff --stat main...HEAD` 只含「允许改动」。
