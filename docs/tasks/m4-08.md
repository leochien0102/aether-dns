## M4-08 上游失败日志可诊断性（**冻结 2026-11-10**）

- **单一目标**：上游失败时，日志指认**真实上游**与**每个上游各自的失败原因**，不再把客户端地址标成 upstream，不再只剩 last error。

## 背景与证据（2026-11-10 10:40 事件）

一次跨项目误判：H28K 上出现 `upstream 127.0.0.1:<port>: upstream timeout after 5 s`，被读成"上游不可达"，实际：

1. 打印的 `peer` 是**客户端**（dnsmasq 源地址与临时端口），不是上游 —— `src/server.rs:302`，对照同文件 `:216` `TCP client {peer}`、`:460` `UDP send {peer}` 的正确用法。
2. 组内**只保留最后一个错误**，上游身份在 `src/upstream_group.rs:34,41` 处丢失（`last_error = Some(error)` 覆盖），因此无法事后判断是哪个上游、也无法区分 reset 与 timeout。
3. proxy 侧据此把原因归到"引擎日志"，proxy 已在 `docs/09` 补充读法；本卡只修日志，不改任何解析/转发语义。

## 做什么（语义冻结）

1. `upstream_group::exchange` 在**全组失败**前，收集每个已失败上游的 `(描述, 错误)` 对；返回聚合错误。
2. 描述格式 `<proto>://<ip>:<port>`，`proto` 取**生效协议**：上游显式协议优先，否则取 `client_protocol`（与 `upstream.rs:17` 的选择一致）。
3. 聚合消息固定为：
   `no upstream answered: <desc>: <err>; <desc>: <err>`
   条目顺序按**配置顺序**，不是完成顺序。
4. **保持 `io::ErrorKind`**：沿用当前"最后一个错误"的 kind（保证 `all_silent` 仍是 `TimedOut`）。
5. `src/server.rs:302` 改为：
   `eprintln!("upstream failed for client {peer}: {error}")`
6. 空组错误 `empty upstream group` 保持原文不变。

示例（两上游，一个拒绝、一个静默）：

```text
upstream failed for client 127.0.0.1:54321: no upstream answered: tcp://127.0.0.1:31082: Connection refused (os error 111); tcp://127.0.0.1:31083: upstream timeout after 5 s
```

## 不做什么

- 不改 5 s 超时、不改组内并行竞速、不改"每查询一条新连接"、不实现 `-p/--repeat-times`。
- 不加时间戳、qname、请求 ID；不改 `listening`/`shutdown` 等 M1 就绪与收尾行。
- 不改其它 `eprintln!` 标签；不改缓存刷新失败"静默保留旧条目"的 M4-01 语义。
- 不碰 aether-proxy / channel，不操作设备。

## 停点

- 需要改 `upstream::exchange` 的返回类型或任何调用方签名 → 停下汇报。
- 既有 `tests/upstream_group.rs` 断言必须修改才能通过 → 停下（说明聚合改变了语义）。
- 发现其它位置也把客户端当上游 → 停下汇报，另开卡，不顺手扩。

2. 新增组层用例 `failure_names_every_upstream`：两上游 = 关闭端口 + 静默；断言错误消息**同时**含两个 `127.0.0.1:<port>`、含超时文本、含拒绝类文本，且两段顺序与配置顺序一致。
