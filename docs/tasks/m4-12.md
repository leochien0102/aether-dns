## M4-12 消除剩余测试的端口预留竞态（**冻结 2026-11-13**）

- **单一目标**：让 tests 里仍在用"bind→drop→立即重绑"朴素预留的进程内用例，改用 `tests/common/in_process.rs` 已有的有界重试启动，消除并行跑全套时的假失败。
- **分支**：`fix/test-port-reservation`
- **卡片版本**：以本卡冻结提交为准（见发卡入口提示）；本卡不记录自身提交号

## 背景与证据

- M4-07 只覆盖了 4 个子进程 harness（`tcp_forward`/`udp_forward`/`tcp_timeout`/`tc_clear` 的 common 版本）。
- `tests/common/in_process.rs` 已经实现进程内等价的有界重试（10 次、失败任务先 join、无 sleep、探测就绪），但**只有** `tests/routing.rs` 与 `tests/tc_clear.rs` 在用。
- 仍在使用朴素预留（`TcpListener::bind(("127.0.0.1", 0))` → 读端口 → `drop` → `server::run_*` 再绑）的进程内用例共 6 个：

  ```text
  tests/cache.rs        tests/cache_refresh.rs  tests/filters.rs
  tests/nft_write.rs    tests/none.rs           tests/verdict.rs
  ```

- 症状：并行跑 `cargo test --all` 时偶发 `assertion failed: !serving.is_finished()`（服务任务因 `EADDRINUSE` 提前结束），单独重跑必过。已观测两次：2026-11-10（`filters.rs`，当时 M4-08 复审）、2026-11-13（`none.rs`，M4-11 复审）。两次都不是被测行为的问题。

## 允许改动

- `tests/cache.rs`、`tests/cache_refresh.rs`、`tests/filters.rs`、`tests/nft_write.rs`、`tests/none.rs`、`tests/verdict.rs`（**只改启动/端口预留 plumbing**）
- `tests/common/in_process.rs`（仅当现有 helper 无法表达某个用例时做最小扩展）
- `reports/M4-12.md`

不改 `src/`、不改 `tests/common/mod.rs`、不改 `review.sh`、不改 `Cargo.toml`/`Cargo.lock`、不改其他仓库。

## 做什么

1. 六个文件统一改为：

   ```rust
   let (port, shutdown, serving) = in_process::start(|port, receiver| async move {
       // 原有 Config 构造（bind_port: vec![port]）与 run_with_* 调用原样搬进来
   }).await;
   ```

   每个用例保留自己的 `Config`、fake、`FakeClock`、`Arc` 共享状态；**每次重试重新构造**，不要跨重试复用已被 move 的值。
2. `cache.rs`/`cache_refresh.rs` 用 `run_with_cache_clock` 时，把 `Arc<FakeClock>` 在闭包里 `clone()` 后传入。
3. 删除各文件里手写的"reserve → drop → spawn → 轮询 connect"段落；不要再引入 sleep。
4. 若某用例在断言里用到端口（如构造上游地址），从 `in_process::start` 返回的 `port` 取值，行为不变。

## 不做什么

- 不改**被测行为断言**（DNS 应答、缓存命中、路由/tag、IP 测试、上游计数等）的文本、期望值或超时预算。
- 允许删除的只有**启动 plumbing 断言**：`tests/filters.rs:83`、`tests/none.rs:197`、`tests/verdict.rs:186` 三处
  `assert!(!serving.is_finished())`。它们位于待删除的就绪轮询内，属性由 `tests/common/in_process.rs` 接管：
  `:36` 在任务提前退出时返回 `Err(startup exited: …)`，`:42-43` 在连接探测成功后再次确认任务未结束，
  并且失败任务会先 join 再换端口重试。删除这三行不是放松断言，而是把同一属性交给更严格的实现。
- 不用 `sleep`/`retry` 掩盖竞争，不放宽 `!serving.is_finished()` 之类的健康断言。
- 不改生产代码、不动 `m4-07` 已覆盖的四个子进程 harness。
- 不改 `tests/common/in_process.rs` 的重试上限（10 次）。

## 停点

- 某用例确实需要**固定端口**（例如断言具体端口号或外部连接固定端口）→ 停下汇报，不要强行改。
- 某用例的启动方式无法用 `in_process::start` 的签名表达（例如需要在 `run` 之前拿到内部状态）→ 停下，说明需要的最小扩展。
- 改造后断言必须修改才能通过 → 停下（说明改动越界）。

## 验收（命令 + 可判定结果）

1. 六个文件逐个单独通过：`cargo test --test cache`、`--test cache_refresh`、`--test filters`、`--test nft_write`、`--test none`、`--test verdict`。
2. 竞争复现：并行跑两个二进制，连续 3 轮全过：

   ```sh
   for i in 1 2 3; do
     cargo test --test filters & cargo test --test none & wait
   done
   ```

3. 全套稳定：`cargo test --all` 连续 5 次全过（记录每轮 passed 数）。
4. `cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、`bash tests/review.sh`（FAIL=0）。
5. 断言核对（按语义，不按行数）：
   - `git diff main...HEAD -- tests/` 中**不得**出现被测行为断言的改动；
   - 唯一允许消失的断言是卡里点名的三处 `assert!(!serving.is_finished())`；
   - 报告必须逐文件列出"删了哪行断言、该属性现在由 `in_process::start` 的哪一行覆盖"，
     并说明为何等价（引用 `tests/common/in_process.rs:36` 与 `:42-43`）。
6. `git diff --stat main...HEAD` 只含「允许改动」。
