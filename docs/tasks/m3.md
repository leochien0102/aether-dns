## M3-02 模式矩阵（执行前确认窗口）

对每个模式：

1. `aether-proxy mode use <mode>`；
2. 等 `status.mode` 生效、`state: running`；
3. 查 CN/gfw/未列域名、LAN dnsmasq、A/AAAA/HTTPS；
4. 查 `nft` 表/集合与代理 HTTP inbound；
5. 记录 `SERVICE_STARTED/RELOAD_APPLIED`；
6. 最后恢复 `bypass_cn`。

## M3-03 T1/T2/T3

1. 当前 T1 记录；
2. 停 Xray（或阻断节点）触发 degraded → 观察 `dns_tier` 降到 T2/T3；
3. 查 DNS（被墙/未被墙/国内）；
4. 恢复 Xray，等待健康检测回 T1；
5. 检查 `degraded_mode`、日志、dnsmasq；
6. 任何一步不可逆则先回滚，不重启设备。

## 已知差距/风险

- M2-08 cache 只做正向 A/AAAA，无后台 refresh；当前 `example.com` 已出现 TTL0。
  这是 M4/P1 项，M3 只记录，不改生产语义。
- 周末观察由 WSL 的 Windows 计划任务 `AetherDnsH28KWeekend` 每 5 分钟只读采样；
  日志在 `aether-dns/dist/logs/h28k-weekend/`；不修改 H28K、不重启设备。
- 任务依赖当前 Windows 用户登录；Windows 休眠时不会采样。- M2-05 单侧失败回退不是 parity；M3 故障演练只观察，不据此改代码。
- 无 IPv6 IP 测试、无 DoT；M3 不扩。
- 模式/T级切换会短暂影响 LAN/DNS；必须在窗口内做，结束恢复基线。
