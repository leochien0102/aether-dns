### M4-02 组件命名统一为 aether-*

要求：

  `chinadns-ng`，避免误解；
- 日志示例（当前）：

```text
aether-proxy: chinadns-ng repeated 1 more times: upstream ... Connection reset
```

目标：日志/事件/限流提示使用逻辑名 `aether-dns`（或统一 `aether-` 名称），
不出现 `chinadns-ng` 字样；回退路径是否显示、如何脱敏待定。

影响面（aether-proxy，非 aether-dns）：

- `aether-proxy/src/lib/const.uc` 的 `CHINADNS_COMPONENT`；
- `daemon.uc` 的 `chinadns_start` 步骤/错误 detail；
- `cmd/log.uc` 的 `chinadns-ng` 日志分类与 rate-limit 提示；

- `po` 翻译、golden/测试、状态 JSON 的 `components` 键；
- 回退路径 `/usr/bin/chinadns-ng` 的显示策略。

待决策：

1. 状态 JSON 的 `components` 键从 `chinadns-ng` 改为 `aether-dns` 是否破坏 LuCI/第三方；
   需要兼容别名还是直接迁移。
2. 回退时 `/usr/bin/chinadns-ng` 是否在 UI 路径中显示；如果显示，如何满足“日志不出现

### M4-04 重启期间 DNS handoff 不得泄漏到直连（P0）

来源：2026-11-06 21:12 授权受控 restart 实测（不是推断）。证据与数据在
`dist/logs/h28k-weekend/startup-gap-analysis.md`、`probe-restart-2026-11-06T2112.csv`
（本地证据，不入库）。

实测：

- 21:12:01.5–07.7 客户端对随机 `x*.google.com` 得到 **NXDOMAIN、约 300 ms**；
- 同一窗口 31053 无监听、Xray 未启动，随机域名不可能命中缓存，
  因此这些应答只能来自直连解析器；
- 机制：`/tmp/dnsmasq.d/aether-proxy.conf` 内容为 `no-resolv` +
  `server=127.0.0.1#31053`；`daemon.uc` 停止路径调用 `apply.dnsmasq_remove`，
  删除 fragment 并重启 dnsmasq；fragment 消失后 dnsmasq 回落到
  `resolv-file=/tmp/resolv.conf.d/resolv.conf.auto`（223.5.5.5）。

影响：每次 restart/升级约有 6 s LAN DNS 绕过代理；被墙域名可能拿到直连结果，
且不产生任何 aether-dns 日志（这段没有监听者）。

目标：restart 不得出现直连解析窗口；用户主动 stop 仍按现行为释放 handoff。

边界：只改 aether-proxy 启停编排；不改 aether-dns 查询语义；不改变 stop 的既有语义。

验收：

1. 同法受控 restart（随机 gfw 域名 10 qps）：无“NXDOMAIN 且约 300 ms”的直连窗口；
2. 设备侧 100 ms 采样 `/tmp/dnsmasq.d/aether-proxy.conf`：restart 全程存在；
3. 主动 stop：fragment 仍被移除、DNS 恢复直连（现有语义不回退）；
4. 恢复后 T1、PROXY_HEALTHY。

待决策：

1. restart 与 stop 的区分方式（init 脚本传 flag、stop 延迟摘除、保留到 start 完成）；
2. restart 期间期望行为是 SERVFAIL 还是短暂排队。

停点：无法在不改 init 脚本的前提下区分 restart/stop 时，停下询问，不自行改 stop 语义。

### M4-05 启动期 SERVFAIL 窗口（P1）

实测（同日两次 restart）：

- 21:12:11.8–13.6：child 已监听 31053、Xray 未监听 31082/31083，
  客户端 58 条 SERVFAIL；设备日志 21:12:11–13 多条 refused；
- 17:21 同类事件 6 条 refused（当时被误读为“只有 6 个查询受影响”）。

根因证据：就绪门只等 TPROXY 31080（`monitor.uc` 的 `wait_xray_port`）；
启动顺序为 `start_chinadns` → `dnsmasq_install` → `resolve_node` → `start_xray_listen`
（`daemon.uc`），DNS 先于 Xray 的 DNS inbound 可用。

目标：T1 启动期间不再出现“有监听、无上游”的窗口。

边界：只调启动顺序/就绪判定；不改运行期路由与列表语义；节点域名仍走直连兜底。

验收：

1. 受控 restart：SERVFAIL 窗口 ≤0.5 s，refused 日志 0 条；
2. 无 LKG 的冷启动同样满足；
3. 节点域名解析不依赖 Xray；
4. 运行期 T1/T2/T3 与模式行为不回归。

待决策：bootstrap 解析路径（LKG 优先 / 直连解析器）、是否同时等 31082 与 31083。

停点：若需改 Xray 渲染或新增 bootstrap 解析器，先停下确认范围。

### M4-06 restart 期间 dnsmasq 两次重启（P2）

实测两段超时：21:11:57.5–01.5 与 07.7–11.6，合计约 8 s。
stop 时 `dnsmasq_remove` 重启一次，start 时 `dnsmasq_install` 再重启一次。

目标：一次 restart 周期内 dnsmasq 重启 ≤1 次，客户端超时窗口 ≤0.5 s。

验收：同法探测 0 条超时；设备侧 dnsmasq 启动次数 ≤1。

待决策：fragment 增删能否用 HUP 生效；或先写 fragment 再统一重启。

依赖：M4-04 的时序决定会影响本卡，M4-06 排在 M4-04 之后。
