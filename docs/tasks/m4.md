## 已确认

### M4-01 cache refresh / stale 修正

M3 已观察 `example.com` TTL0；当前 M2 cache 只做正向 A/AAAA，无后台 refresh，
过期后以 TTL0 服务到 `cache-stale` 上限。M4 第一优先，具体语义在 M3-REPORT 后冻结。

### M4-02 组件命名统一为 aether-*

要求：

- 不使用 `chinadns-ng` 作为 aether-dns 的别名/逻辑组件名；
- 概览页组件显示 **`aether-dns`**，路径 **`/usr/bin/aether-dns`**；
- 可回退使用 `/usr/bin/chinadns-ng`，但 UI/日志不得把当前运行组件显示成
  `chinadns-ng`，避免误解；
- 日志示例（当前）：

```text
aether-proxy: chinadns-ng repeated 1 more times: upstream ... Connection reset
```

目标：日志/事件/限流提示使用逻辑名 `aether-dns`（或统一 `aether-` 名称），
不出现 `chinadns-ng` 字样；回退路径是否显示、如何脱敏待定。

影响面（aether-proxy，非 aether-dns）：

- `aether-proxy/src/lib/const.uc` 的 `CHINADNS_COMPONENT`；
- `daemon.uc` 的 `chinadns_start` 步骤/错误 detail；
- `cmd/log.uc` 的 `chinadns-ng` 日志分类与 rate-limit 提示；
- `monitor.uc`、`render/nft.uc` 注释/事件；
- LuCI `overview.js`、`updates.js`、`advanced.js`、`logs.js`；
- `po` 翻译、golden/测试、状态 JSON 的 `components` 键；
- 回退路径 `/usr/bin/chinadns-ng` 的显示策略。

待决策：

1. 状态 JSON 的 `components` 键从 `chinadns-ng` 改为 `aether-dns` 是否破坏 LuCI/第三方；
   需要兼容别名还是直接迁移。
2. 回退时 `/usr/bin/chinadns-ng` 是否在 UI 路径中显示；如果显示，如何满足“日志不出现
   chinadns-ng”的要求（逻辑名与物理路径分离）。
3. `aether-xray` 组件名是否同步改为 `aether-xray`（当前 `xray`），以及更新通道/PO 的兼容。

### M4-03 版本号统一为 x.y.z

要求：

- aether-dns 不再用日期版本（`2026.11.04`），改为 `x.y.z`；
- 与 aether-proxy 的版本规则统一（当前 proxy `0.6.3-r4`）；
- `-V` 第二字段、ipk 版本、Cargo 版本、测试、README/report 同步；
- aether-proxy 的版本检查必须按引擎区分，**不能继续用 chinadns-ng 的
  `2025.08.09` 最小值去比较 `0.6.3`**（否则 0.6.3 会被判旧）。

待决策：

1. 是否与 aether-proxy 同号（例如都 `0.6.3`），还是仅采用 x.y.z 格式且独立递增；
2. 若同号，aether-proxy 发版时是否强制同步 aether-dns 版本；
3. aether-dns 的最小支持版本如何声明（engine-specific minimum）。

## 候选（M3-REPORT 后再定）

- NODATA/NXDOMAIN 负缓存；
- response question 防御性匹配（非 parity，安全项）；
- TCP 连接数上限；
- DoT（仅真实配置使用）；
- IPv6 set 读写、cache-db、hosts/local RR、6 自定义组、
  `noip-as-chnip`/`fair-mode`/`reuse-port`；
- aether-proxy DNS/Xray 双引擎切换按钮、插件/capability 模型（独立项目）。
