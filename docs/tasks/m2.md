# M2 任务卡：P0 行为等价（aether-proxy profile）

> **项目与范围**：本文件的任务卡全部属于 **aether-dns** 仓库（`/workspace/openwrt/aether-dns`）。
> 执行时只在本卡 worktree（`/workspace/openwrt/aether-dns-wt/<卡号>`）中读写；
> **不准修改 aether-proxy、`archive/`、`openwrt-actions/` 或 `/workspace/openwrt` 下的其他仓库**。
> 任务卡必读的 aether-proxy renderer/fixtures/data 只读。执行约定见 [README.md](README.md)。

M2 目标：把 M1 的“所有查询走第一个 trust”替换为 **chinadns-ng P0 行为**，以
`aether-proxy/tests/fixtures/*/expected/chinadns.conf` 和 M0 的 `baseline.json` 为准。
M2 只做 P0；P1（hosts、DoT、cache-db、完整 CLI、chnlist-first、6 组等）不做。

**卡规则**：一张卡一个目标、一句话；验收必须是可执行命令/可判定结果；不写“并/同时/顺带”。

## 2. 任务卡（M2-01–M2-04）

### M2-01 域名列表与 tag/组解析

- **单一目标**：给定 qname + Config，返回 `chn` / `gfw` / `none` / 自定义组（含组序号）。
- **分支**：`m2/lists`
- **必读**：[PARITY-MATRIX.md](../../PARITY-MATRIX.md) P0-04/07、[PLAN.md](../../PLAN.md) §2、
  `aether-proxy/aether-proxy/src/lib/render/chinadns.uc`（只读）、M0 `coverage.json`。
- **允许改动**：`src/lists.rs`、`tests/lists.rs`、`tests/data/lists/`。
- **做什么**
  1. 读取 `gfwlist-file`、`chnlist-file`、每个 `group-dnl` 的文件；列表格式按上游：
     空白分隔 token；忽略空/`#` 开头/`.` 开头/`.` 结尾的 token；不做大小写转换。
  2. **8 层截断（parity）**：上游 `MAX_NAME_LEVEL = 8`。token 通过边界校验后，从右往左保留
     8 个 label；保留部分每个 label 长度必须 ≤63；左侧多余 label 直接丢弃、不再校验。例：
     `gsp4-cn.ls.apple.com.edgekey.net.globalredir.akadns.net`（9 层）加载为
     `ls.apple.com.edgekey.net.globalredir.akadns.net`（8 层）。
     qname 匹配只考虑最后 `min(label_count, 8)` 个后缀；最长后缀/label 边界不变。
     依据：`dnl.c:347` `MAX_NAME_LEVEL 8`、`dnl.c:353-384` `check_name`；
     真实数据 `aether-proxy/aether-proxy/files/data/apple.txt:64`。
  3. 匹配 qname 的后缀，必须按 label 边界；**最长后缀优先**；同一 qname 命中多条列表时按优先级。
  4. 优先级（按上游 `dnl.c`）：自定义组 **后声明者优先**（renderer 注释 low→high），
     自定义组整体优先于 chn/gfw；chn/gfw 默认 **gfw 先**（`chnlist-first` 不在 P0）；
     未命中返回 `default-tag`（缺省 `none`）。
  5. 提供 `RouteTag`（chn/gfw/none/group index）与 `resolve(qname, &Config) -> RouteTag`；
     不联网、不读 config 路径以外的文件。
  6. 测试：exact、子域、最长后缀、label 边界（`notexample.com` 不匹配 `example.com`）、
     gfw/chn 冲突、自定义组优先级、default-tag、注释/空行/多 token、多个文件追加；
     以及 8 层截断：加载 apple.txt:64 的 9 层域名、8/9 层 qname 命中、7 层不命中、10 层 token 截断。
- **不做什么**：不实现 `chnlist-first`、`hosts`、`cache`、路由/网络；不改 config/dns/server。
- **停点**：`chnlist-first` 出现在 fixture；其他 `check_name` 异常 token（非 8 层截断）与源码不一致——
  停下询问。8 层截断已确认并纳入本卡，不再停。
- **验收**
  1. `cargo test --test lists` 退出 0；≥15 个匹配/优先级/截断用例。
  2. 测试打印 `N/N lookup cases passed`；全部标签/组序号断言；包含 apple.txt:64 的 9→8 层用例。
  3. 报告贴出优先级依据（`dnl.c` 的 `dnl_init`/`dnl_get_tag`）与测试输出。

### M2-02 上游组并发

- **单一目标**：对一个上游组（多个 `Upstream`）并发查询，返回首个合法响应。
- **分支**：`m2/upstream-group`
- **必读**：`src/upstream.rs`、`src/config.rs`、M0 baseline 的 `t922-mixed`/`t923-*`、PLAN M2。
- **允许改动**：`src/upstream_group.rs`、`tests/upstream_group.rs`、`src/upstream.rs`（仅暴露必要的校验/构造）。
- **做什么**
  1. 输入 `&[Upstream]`、query、客户端协议；对每个上游并发调用现有 `exchange`，返回第一个
     合法响应；其余任务取消。
  2. 单个上游失败/超时不拖住整组；整组无合法响应时返回错误。
  3. 保持客户端协议跟随（显式 `udp://`/`tcp://` 优先），复用 M1 的 5 s/单次。
  4. 测试：两上游一慢一快、首个返回非法/不匹配 ID 再取第二个、全部失败、两个都合法取先到、
     UDP/TCP 混合；fake upstream 不联网外网。
- **不做什么**：不做路由/tag/IP 测试/nftset/cache；不做重复发送 `repeat-times`、fair-mode。
- **停点**：多上游“首个合法”与 M0 基线不一致；需要 `repeat-times` 才能过 P0——停下询问。
- **验收**
  1. `cargo test --test upstream_group` 退出 0；≥5 个场景。
  2. 测试打印 `N/N group cases passed`；断言只用了一组合法响应、其余被取消。
  3. `cargo test --all` 与 `tests/review.sh` 仍全过。

### M2-03 nftset netlink 模块

- **单一目标**：提供 `family@table@set` 的成员测试与批量添加（test-then-add/ACK/EEXIST 重试）。
- **分支**：`m2/nftset`
- **必读**：[M0-REPORT.md](../../M0-REPORT.md) §2、`spikes/m0-nftset/src/netlink.rs`（参考，重写）、
  IMP-004。
- **允许改动**：`src/nftset.rs`、`Cargo.toml`/`Cargo.lock`（加 `libc`）、`tests/nftset.rs`、
  `tests/nftset_acceptance.sh`。
- **做什么**
  1. 解析 `inet@table@set`（`ip`/`ip6`/`inet`），构造 `GETSETELEM` 成员测试与 `NEWSETELEM`
     批量添加；interval begin/end；batch begin/end；带 ACK。
  2. 按 IMP-004：先逐 IP 测试，再批量加缺失；`-EEXIST` 重试一次；不缓存 handle；
     `-ENOENT`/`-EPERM` 返回可识别错误，不 panic。
  3. 测试（`NFT_TEST=1` 才执行；无该环境变量时打印 SKIP 并返回）：
     在 `unshare -Urn` 的新 netns 中用 `nft` 建 `m2nft` 表/集合，验证 found/not-found、
     add、重复/区间内 EEXIST、缺失 set、删表重建。
  4. `tests/nftset_acceptance.sh`：`unshare -Urn -- bash -c 'nft ...; NFT_TEST=1 cargo test --test nftset'`；
     不需要 sudo/root 宿主。
- **不做什么**：不接 server、不做 add-taggfw-ip/group-ipset 路由、不做 IPv6 业务、不用 `nft` 实现生产路径。
- **停点**：unprivileged userns 在某些环境不可用；内核 netlink 行为与 M0 不一致——停下询问，
  不退回 `nft` CLI 实现。
- **验收**
  1. `bash tests/nftset_acceptance.sh` 退出 0；输出各场景 PASS。
  2. 直接 `cargo test --test nftset` 在无 `NFT_TEST` 时 SKIP、退出 0；`cargo test --all` 不被破坏。
  3. 报告贴出 netns 命令、场景与耗时；不改 aether-proxy。

### M2-04 按 tag/组路由到上游

- **单一目标**：server 按 `chn` / `gfw` / 自定义组 / `default-tag` 选择对应上游组并转发；
  `tag:none` 暂保持 M1 的“第一个 trust”回退（M2-05 再替换）。
- **分支**：`m2/routing`
- **必读**：M2-01 的 `src/lists.rs`、M2-02 的 `src/upstream_group.rs`、M1 `src/server.rs`、
  M0 baseline 的 t14-gfw / t14-bypass-cn / t14-global 场景。
- **允许改动**：`src/lists.rs`（新增 load-once `Router`，保留现有 `resolve` 与测试）、
  `src/server.rs`、`src/main.rs`（模块声明）、`tests/routing.rs`。
- **做什么**
  1. `Router::load(&Config)` 在启动时把 gfw/chn/group-dnl 全部读入内存；server **不得**每查询读文件。
     `resolve` 的优先级、8 层截断、大小写语义保持不变；缺文件继续跳过（上游行为）。
  2. server 启动时构建 Router；查询按 `RouteTag` 选组：
     `Chn`→`china_dns`、`Gfw`→`trust_dns`、`Group(i)`→`groups[i].upstream`；
     用 M2-02 的 `upstream_group::exchange`，保留现有响应 ID/RA/additional/SERVFAIL 处理。
  3. `RouteTag::None` **临时**回退到第一个 `trust-dns`，保持 M1 的 22 启动/转发/信号测试不回归；
     在日志/注释/报告中明确标注“M2-05 替换”，不得写成 parity。
  4. 组上游为空或配置缺组：该查询返回 SERVFAIL（启动仍成功，除非配置校验失败）。
  5. 集成测试：本地 fake upstream（china/trust/两个 group），断言 gfw/chn/group0/group1/default-tag
     只命中目标组；`tag:none` 回退 trust；UDP/TCP 客户端至少各一例。
- **不做什么**：不做 `tag:none` 双查询/IP 测试（M2-05）、nftset/cache/过滤、`chnlist-first`、
  P1；不改 config/dns/upstream/Cargo/既有测试。
- **停点**：`tag:none` 行为被要求在本卡实现；列表优先级与 M2-01 不一致；组上游为空但 fixture 要求启动失败——
  停下询问。
- **验收**
  1. `cargo test --test routing` 退出 0；≥6 个路由用例。
  2. `cargo test --all`、`tests/review.sh` 全过；M1 的 UDP/TCP/lifecycle/startup/forward 不回归。
  3. 报告贴出每个 tag 的命中组、`tag:none` 临时回退说明与测试输出。
