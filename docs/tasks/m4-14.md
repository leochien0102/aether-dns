## M4-14 收紧 verify-assets.sh 的可执行位断言（**冻结 2026-11-14**）

- **单一目标**：把 `tests/ci/verify-assets.sh` 对无扩展名裸二进制的权限断言，从"至少 rwxr-xr-x"收紧为"恰好 0755"，并让 0777 / 02755 / 04755 这类多余位有可复跑的负向证据。
- **分支**：`test/verify-assets-mode`
- **卡片版本**：以本卡冻结提交为准（见发卡入口提示）；本卡不记录自身提交号

> 来源：交接文档 §6 第 5 条（2026-11-14 复核结论）。所有者决定：**不返工已发布的 1.0.2**，单独出这张小卡修校验器。

## 背景与证据

`tests/ci/verify-assets.sh:58` 现为：

```python
require(path.stat().st_mode & 0o755 == 0o755,
        f'Raw binary must have 0755 permission bits: {path.name}')
```

- Python 中 `&` 的优先级**高于** `==`，所以这不是优先级 bug，实际语义是 `(st_mode & 0o755) == 0o755`，即"逐位至少满足 rwxr-xr-x"；
- 因此 `0777`、`02755`（setgid）、`04755`（setuid）都能通过，与错误信息承诺的"0755"不符；
- 现有资产本身是 0755（CI 里 `chmod 0755` 后立即断言），所以**已发布的 1.0.2 无问题**，这只是让校验器与其名字一致。

实测（Python 3，2026-11-14）：

```text
st_mode  当前写法   S_IMODE 写法
0755     True      True
0745     False     False
0751     False     False
0777     True      False
02755    True      False
0644     False     False
```

## 允许改动

- `tests/ci/verify-assets.sh`（断言一行 + 注释；`import stat`）
- 新增 `tests/ci/verify-assets-selftest.sh`
- `.github/workflows/release.yml`（在 `verify` 作业里加一步调用自测，**只读副本**）
- `reports/M4-14.md`

不改 `src/`、`Cargo.*`、`openwrt/`、版本号、其他仓库。

## 做什么

### 1. 收紧断言

```python
require(stat.S_IMODE(path.stat().st_mode) == 0o755,
        f'Raw binary must have exactly 0755: {path.name}')
```

- `S_IMODE` 掩到 `0o7777`，能挡住 setuid / setgid / sticky 与世界可写；
- 注释写明为什么不用 `& 0o755 == 0o755`（那是"至少"语义），以及 Python 的 `&` 优先于 `==`（避免下一次再被误判成优先级 bug）。

### 2. 新增可复跑的自测 `tests/ci/verify-assets-selftest.sh`

用法：`sh tests/ci/verify-assets-selftest.sh <含有完整六资产 + SHA256SUMS 的目录>`。

对同一份真实资产集做以下断言（每轮把资产**复制到临时目录**，绝不修改传入目录）：

| 场景 | 对某个裸二进制执行 | 期望 |
|---|---|---|
| 基线 | 不改（应为 0755） | 校验通过（exit 0） |
| 世界可写 | `chmod 0777` | 校验失败（exit 非 0） |
| setgid | `chmod 02755` | 校验失败 |
| setuid | `chmod 04755` | 校验失败 |
| 无执行位 | `chmod 0644` | 校验失败 |

要求：
- 逐条打印 `PASS/FAIL 场景名`，末尾打印统计并以退出码反映结果；
- 失败场景必须是因为**权限断言**失败，而不是别的检查先挂：断言 stderr 含 `must have exactly 0755`；
- 不改 `verify-assets.sh` 的其它检查；
- 副本目录用 `mktemp -d`，结束时清理。

### 3. 接入发布作业（只读副本）

`.github/workflows/release.yml` 的 `verify` 作业，在生成 `SHA256SUMS` 并跑过 `verify-assets.sh assets` 之后，加一步：

```yaml
      - name: Self-test the asset checker
        run: sh tests/ci/verify-assets-selftest.sh assets
```

该步骤只读取 `assets/`，自测脚本内部复制到临时目录，不得改动待发布资产。

## 不做什么

- 不重新发布 1.0.2、不改版本号、不推 tag、不打 Release。
- 不改 `verify-assets.sh` 里除权限断言之外的任何检查（名称集合、校验和、ipk control、Source 规则都保持）。
- 不改 `check-version.sh`、不改 `openwrt/`、不改 `src/`。
- 不引入 Python 依赖（只用标准库 `stat`、`pathlib`、`subprocess`）。

## 停点

- 若无法取得一份真实的六资产集合（例如 `gh` 不可用且无法本地产出），**停下汇报**，由设计负责人提供目录后再继续；不要用伪造的 ipk 让 ipk control 检查失去意义。
- 若自测发现失败场景是被别的检查拦下（而非权限断言），停下汇报，不要放宽断言。
- 若需要在发布作业里写权限（`chmod` 原件）才能跑通 → 停下（违反"不修改待发布资产"）。

## 验收（命令 + 可判定结果）

1. `sh tests/ci/verify-assets-selftest.sh <真实资产目录>`：5 个场景全部符合预期，退出 0；报告贴完整输出。
2. 单独复验：`chmod 0777` 与 `chmod 02755` 的副本都必须因 `must have exactly 0755` 失败（报告贴这两条 stderr）。
3. 基线 0755 仍通过（确认没有把正常路径改坏）。
4. `bash tests/review.sh`（FAIL=0）。
5. `git diff --stat main...HEAD` 只含「允许改动」。

## 取得真实资产集合的方式（供实现者）

优先：`gh release download v1.0.2 -D /tmp/m414-assets --clobber`（仓库已 public）。
该目录应含 4 个包 + 2 个裸二进制 + `SHA256SUMS`，与 Release 页面一致。

**下载后必须恢复基线权限**（这是夹具准备，不是放宽断言）：

```sh
chmod 0755 /tmp/m414-assets/aether-dns-1.0.2-r1-aarch64_generic \
            /tmp/m414-assets/aether-dns-1.0.2-r1-x86_64
```

原因：GitHub Release **不保存可执行位**，下载得到 0644；而 CI 里 `verify` 作业的资产是用 tar 跨作业传递的，
位仍是 0755，所以发布作业中的自测步骤**不需要**这一步。校验器的判定对象是"CI 产出的资产"，
下载目录只是本地夹具；把基线恢复成 0755 才能验证"0755 通过、多余位失败"。
自测脚本本身**不得**替调用方 chmod 基线（否则会掩盖真实的权限回归）。
