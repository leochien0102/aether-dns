# 01 方案草案

状态：2026-11-02 初稿，等待所有者与交叉审查。本文提出实现方向，不授权开始全量开发。

第一轮审查修订：范围拆为通用核心与形态 A 兼容能力；具体处理见 [审查答复](review/2026-11-02-response.md)。未来形态 B 不是现行兼容契约。

## 1. 目标与非目标

### 目标

1. 用 Rust 建立长期可维护的独立 DNS 组件，不继承旧 Zig 工具链约束。
2. 覆盖 aether-proxy 当前实际依赖的 DNS 行为；替换不要求同时实施多出口分流。
3. 为报文、并发、内存、缓存、netlink 与重载建立可验证的边界。
4. 允许未来增加上游传输或匹配能力，不要求重写调度和缓存。
5. 组件可在没有 aether-proxy 的情况下使用标准配置独立运行。

### 非目标

- 递归解析器、权威 DNS、DNSSEC 验证器、DHCP 服务。
- Xray/SOCKS/HTTP 代理协议实现，或 OUTPUT 透明代理。
- 节点管理、自动测速、多出口选择、T1/T2/T3 自动切换。
- 第一版提供 DoH、DoQ、FakeDNS、规则脚本或插件 ABI。
- 完整兼容 ChinaDNS-NG 命令行、缓存数据库、所有历史行为。
- 第一版承诺 IPv6 代理。DNS 传输/AAAA 支持与代理 IPv6 是不同能力。

## 2. 所有权与进程关系

| 职责 | 所有者 |
|---|---|
| 用户配置、WAN DNS 展开、节点 LKG、引导地址、Xray tunnel 配置 | aether-proxy |
| 节点健康、T1/T2/T3 选择、故障放行 | aether-proxy monitor |
| 域名分类、选择应答、转发、缓存、过滤 | aether-dns |
| nft 表/集合的创建、删除、整表替换、持久化 | aether-proxy |
| 可选地域分类与指定集合地址写入 | 形态 A 兼容层；后端待 P0 定稿，权限不细分到单集合 |
| DHCP、本地域名、系统 DNS 入口 | 系统 dnsmasq |
| 加密代理传输 | Xray |

aether-dns 在集成模式由 aether-proxy 管理，不再同时启用一个会竞争同一端口的独立 procd 实例。独立运行模式可另有 procd 配置；两种模式互斥，生命周期不重复管理。

默认只绑定 loopback，集成监听端口由调用方提供；不把 aether-proxy 的端口或表名写死在引擎里。上游使用 IP 字面地址与显式端口；第一版不允许为了连接上游再经系统解析器解析该上游，避免引导循环。

## 3. Rust 架构建议（待原型验证）

建议一个可执行文件、一个内部库，不先拆多 crate workspace：

| 模块 | 输入 / 输出与约束 |
|---|---|
| `config` | JSON → 校验后的不可变配置快照；含 schema 版本 |
| `wire` | DNS 协议库的窄封装；规范化问题、校验应答、编码与截断 |
| `policy` | 域名 → 上游组或双组判定策略；不做网络 I/O |
| `transport` | UDP/TCP，后续可选 DoT；只返回有期限的查询结果 |
| `scheduler` | 预算、并发、重试、单飞合并、取消、组内竞争 |
| `selection`（可选兼容层） | 国内/可信候选 → 唯一应答；显式状态机，不是通用核心必需项 |
| `cache` | 应答与判决缓存、单调时钟、策略代次 |
| `classifier`（可选兼容层） | 地域成员测试；实时内核查询或同源 CIDR 快照待选，不与写入绑定 |
| `nft_writer`（可选兼容层） | 地址写入、ACK/错误、重建后的同步；通用核心可不构建 |
| `control` | 本地 Unix socket 控制协议、原子配置切换 |
| `observability` | 有界计数、状态、脱敏日志 |

候选：Tokio（单 worker 起步）+ DNS 协议库（如 hickory-proto）+ serde/serde_json。仅用协议解析层，不把完整递归解析服务引入为依赖。

这不是依赖批准清单：原型必须确认当前稳定版本、MSRV、feature、维护与安全状态、许可证、目标支持和资源成本。DNS 协议库若重编码时不能安全处理未知 RR，必须限制支持范围并阻断替换，不能静默损坏应答。

优先安全 Rust；本项目代码默认禁止 `unsafe`。netlink 若确需 FFI/unsafe，只能集中在小模块，逐处说明不变量并审查；依赖自身的 unsafe 也属于风险登记，不能因本项目无 unsafe 就声称完全内存安全。

P1 只验证协议/传输/调度骨架，不实现地域分类、双组选择或集合写入；这些仅在明确承诺替换形态 A 后进入 P2。模块独立不代表立刻引入多 crate、插件或动态分发框架。

## 4. 域名策略

### 4.1 匹配规则

- 第一版只支持精确匹配与按 DNS 标签边界的域名后缀，不支持正则/keyword。
- **先最具体，后优先级**：精确项优于相同名字的后缀项；后缀之间最长后缀优先；同种匹配键重复时，显式较大 `priority` 胜出。
- 同匹配键、同 priority 但动作不同：配置校验失败；完全一致可以去重。不能依赖哈希表遍历顺序。
- 规则文件为 ASCII 域名 / A-label，每行一项；允许空行与整行 `#` 注释。配置域名转小写、允许去掉一个结尾点，拒绝非法项与静默截断。空文件合法；缺失文件失败。
- DNS wire 名字按协议处理，不因 HTTP 风格主机名校验拒绝带下划线等合法查询；不可映射到策略文本的名字走默认策略，不缓存为另一个名字。
- 现有 boot 列表同样采用最长匹配，不冒称组优先级能覆盖更具体的子域名。节点的精确域名必须生成明确规则。

策略动作只包括：`forward(group)`、`select(china, trust, classifier)`、`nodata`。组是有名字的上游集合，`china`/`trust` 是集成配置的名字，不是硬编码类别。

### 4.2 组内竞争

第一版保留同组并发查询，不实现 RTT 学习或隐式顺序回退。不同信任等级的上游不能混到同一组。

- 首个通过校验的 NOERROR 应答（含合法 NODATA）或 NXDOMAIN 胜出；SERVFAIL/REFUSED 留作错误候选，等待其他上游直到成功或整体截止。
- 所有上游失败时返回 SERVFAIL；达到整体期限也主动结束，不把连接无限挂住。
- 截止时间覆盖排队、连接、发送、接收、协议解析和必要的集合操作，不因重试重置。
- 使用分开的组/类别预算，可信上游挂住不能占满国内与引导查询全部资源。
- 每组并发数、组数量、TCP 连接池、等待队列都必须有上限。

## 5. 国内/可信双组选择

这是一项**地域启发式选择**，不是密码学污染检测，不能宣称国内 IP 就意味着结果可信。

未分类查询并发发送到两个组。建议按以下规则处理 A（首版集成配置过滤 AAAA）：

| 国内结果 | 可信结果 | 动作 |
|---|---|---|
| NOERROR，问题名经有界 CNAME 链可达的 A 非空，且全部属于分类集合 | 任意 | 选择国内结果；可信迟到结果丢弃 |
| 有非国内地址、NXDOMAIN、NODATA、错误或超时 | 有合法成功结果 | 选择可信结果 |
| 尚未完成 | 先返回合法结果 | 暂存可信结果，等国内结果或整体期限，再按上两条选择 |
| 分类数据源不可用/代次未确认 | 有合法结果 | 选择可信结果并报告分类不可用，不把失败当“国内”；若仍需写集合，另按写入策略处理 |
| 国内 UDP 应答 TC=1 | 任意 | 不用残缺地址做判定，先在剩余期限内 TCP 重试；未得完整可接受结果则用可信，否则 SERVFAIL |
| 国内结果不被接受 | 可信也失败 | SERVFAIL，不隐式转用国内结果 |

固定上游 `23af4b1b` 的 `dns.c:test_ip()` 由 answer 段第一条 A/AAAA 决定地域分类，且不验证 owner 是否属于问题名的 CNAME 链。本文“链可达 + 全部地址命中”为**建议的有意修正，待批准**，不是等价行为。混合地址可能改变最终解析/流量出口，必须用顺序反转、无关首条 A、CNAME 夹具及用户说明覆盖。首版不把 DNAME 链纳入地址分类；无法证明归属时选择可信组。

现有国内 NODATA 采用 trust 与默认关闭 `noip-as-chnip` 一致。TC 则不同：上游存在接受截断应答路径；本文先补全再分类是另一项有意修正，必须登记。

非 A/AAAA 查询在双组策略下建议只送可信组；AAAA 在过滤关闭时若没有 IPv6 分类能力，也只送可信组。完整 IPv6 分类另行验收。上述差异须在迁移闸门审定。

第一版建议暂不启用独立的判决缓存，减少永久地域判定导致的错误固化；应答缓存仍启用。若性能证据要求判决缓存，另加有 TTL、容量和策略代次的实现，不能照搬无限期判决。此项属于兼容差异。

暂不做负缓存与判决缓存的叠加代价必须单独量化：每次客户端查询触发的 china/trust 请求数、隧道 DNS 字节、NXDOMAIN/NODATA 比例和延迟。P3 纳入可选 RFC 2308 负缓存候选，是否默认启用由测量与协议验收决定；不缓存 SERVFAIL，不凭性能压力跳过正确性验证。

## 6. DNS wire 与传输契约

- 首版处理标准 QUERY、一个 question、IN class；可解析但不支持的 opcode 用 NOTIMP，其他可安全应答的非法请求用 FORMERR。无法可信定位报头/问题的畸形报文直接丢弃并计数。
- 过滤 AAAA/HTTPS 时本地返回 NOERROR/NODATA，保留 question；不查询上游。过滤是策略，不是递归验证；AD 不得因本地合成而置位。
- 当前 aether-proxy 使用全局 AAAA 开关，但上游还支持按组及 `ip:china`/`ip:non_china` 条件过滤。后两项不是当前集成配置的必需能力，列为未来 IPv6 扩展；不把全局布尔描述为上游完整能力，也不保证其自动等价于“只给代理流量放 AAAA”。
- 应答验证至少包含上游端点、事务 ID、QR、opcode、question 的名字/type/class 和结构；UDP 使用随机化 ID 与源端口，迟到应答不可串到新事务。
- UDP 上游 TC=1：在剩余预算内向同一端点 TCP 重试。TCP 上游支持两字节 framing、部分读写、多个消息及合法最大长度，不使用固定 1472 字节缓冲。
- 客户端 UDP 无 EDNS 时按 512 字节，有 EDNS 时按客户端大小与服务端上限的较小值；超大应答由协议库安全编码为 TC 应答，不能直接切字节破坏 RR。客户端 TCP 不按 UDP 上限截断。
- TCP 客户端长连接与流水线有独立连接数、在途数和空闲期限；ID 冲突的处理需原型验证，不能仅按 DNS ID 全局索引。
- TCP 上游先做有界连接复用；第一版建议一条连接同一时刻只处理一笔事务，以免直接引入复杂 ID 多路复用。取消/超时后关闭该连接，禁止残留应答被下一请求消费。
- EDNS 首版支持单 OPT、版本 0 的基本尺寸/DO 信号；不缓存含 ECS、COOKIE 或未知 EDNS option 的请求，不把不同选项查询合并。端点级 COOKIE 等可能需额外处理，P1 必须验证后确定透传/拒绝范围。
- 不做 DNSSEC 验证、不声称 AD 可信；转发默认清 AD，保留上游 DNSSEC RR 与请求 DO/CD 语义。过滤与策略改写不承诺端到端 DNSSEC 验证成功；严格验证客户端属于明确限制。
- 未支持 TSIG/SIG(0)、UPDATE、AXFR/IXFR；识别并拒绝，不以修改 ID 的普通转发破坏签名。
- 未知 RR 的安全编码、扩展 RCODE、BADVERS、EDNS 错误应答必须进入 P1 验证；这些是协议库选型阻断项，不能只测 A 记录。

## 7. 缓存与副作用

### 应答缓存

- 使用单调时钟；同时设置条目数与字节上限，LRU 或等价有界淘汰。
- 第一版仅缓存能证明安全重放的 NOERROR 正应答；TTL 取必需 RRset 的最小值，上限可限制，绝不抬高上游 TTL。负应答正确转发但不缓存，负缓存可后续按 RFC 2308 引入。
- key 至少区分规范问题名、qtype/qclass、DO/CD/RD、有效策略代次；有 ECS/COOKIE/未知 option、非标准 flag 时绕过缓存及单飞。
- 缓存存语义应答或可安全重编码的表示，不能盲改原始字节中的 ID/TTL。未知 RR 无法安全处理时只允许经验证的无损转发，不缓存；若转发也无法保证则拒绝候选库。
- 过期应答仅在 `stale_seconds>0` 时允许；返回 TTL=0，后台刷新单飞。默认候选值为 3600 秒，以匹配集成现状量级；属于可用性折中，不承诺 TTL 过期数据仍正确。
- **候选策略：配置重载一律清空逻辑缓存与判决，不做跨代保留。** 这是第一版为了可靠性选择的简单方案。未来再按策略指纹精细复用。

### nft 副作用

分类与写集合不由缓存隐式跳过。只有最终选中的、问题名经受支持 CNAME 链可达的 A 才允许写入；不写竞争失败组结果、不写无关 additional、不写配置禁止的保留地址。

即便命中缓存/过期应答，也执行需要的集合同步检查。集合操作失败不能悄悄表现成一次成功的正常代理解析；详细契约见 [02](02-compatibility.md)。

## 8. 配置与重载

建议 JSON，字段名不照搬 ChinaDNS-NG 命令行；`schema_version=1`，未知字段报错，不允许回退到部分解释。以下仅为**结构示意，不是可运行配置或完整 schema**：

```json
{
  "schema_version": 1,
  "listen": ["127.0.0.1:31053"],
  "control_socket": "/var/run/aether-dns/control.sock",
  "upstreams": {
    "local": {"transport": "udp", "address": "192.0.2.53:53"},
    "tunnel": {"transport": "tcp", "address": "127.0.0.1:31082"}
  },
  "groups": {
    "china": {"members": ["local"], "strategy": "race"},
    "trust": {"members": ["tunnel"], "strategy": "race"}
  },
  "rules": [],
  "default_action": {"type": "forward", "group": "china"},
  "filter_qtypes": [28, 65]
}
```

本地 CLI 契约建议：

| 命令 | 行为 |
|---|---|
| `aether-dns check -c PATH --json` | 无需 daemon；验证配置/规则文件/预算，不绑定监听、不写 nft、不探测公网 |
| `aether-dns run -c PATH` | 前台运行，交给调用方监督 |
| `aether-dns ctl -s SOCKET reload --expect-generation N --json` | 从启动时固定配置路径加载完整快照，返回应用结果 |
| `... status --json` | 版本、代次、配置摘要、上次重载错误、预算及有界统计 |
| `... flush-cache --json` | 清缓存且终结旧查询回填资格；不修改 nft |
| `... sync-sets --json` | 表替换完成后的集合重探测与缓存地址重放，返回完成/失败 |

CLI 输出协议也带版本；退出码建议 0 成功、2 配置错误、1 运行失败。命令尚未实现，P0 审定后才能生成 schema 与接口测试。

**集成基线建议为 restart-v1**：首轮 aether-proxy adapter 保留“校验后重启子进程、旧二进制+旧配置重启回滚”的模型，不直接接入以下热重载协议。控制 socket、代次切换与集合屏障是 hot-v2 候选，只有冻结并验证 [02 §6.1](02-compatibility.md#61-集成接口候选契约p0-必须冻结) 后才能启用，不是 P1 或首次替换的先决条件。

以下为 **hot-v2 候选引擎行为**，不是现有外层 reload 的描述。重载步骤：读取受大小限制的文件 → 解析并建立新规则快照 → 检查引用/资源 → 必要的运行态预检 → 原子切换代次 → 取消旧代查询 → 返回新代次。任一步提交前失败保留旧配置；提交后失联需查询状态，不能当作未生效。

- 所有查询绑定 `Arc<ConfigSnapshot>` 与代次；提交缓存、nft 写入、向客户端发送前复核代次。
- 切换时旧查询结束为 SERVFAIL，不能把旧可信等级应答送入新策略；TCP/UDP 监听 socket 尽量复用。
- 已发送的 netlink 请求不能靠取消 Rust task 回滚。重载前需在有界期限内排空旧写入；无法确认 ACK 时拒绝重载并要求外部恢复，不宣称内核副作用也被原子切换。
- 监听地址/控制 socket/权限变化第一版要求受控重启，不伪装成支持热重载。
- 外层 dnsmasq 的缓存不会因为引擎重载自动消失。aether-proxy 在涉及信任/规则变化时等待 reload ACK 后清外层缓存，失败则报告整体操作未完成。
- 输入规则文件由调用方放在不可变版本目录，配置引用固定目录；先完整写入再原子切换配置文件，避免一次 reload 读到新旧混合文件。

## 9. 安全、资源与状态

所有数量都要可配置且有硬上限：客户端/上游 TCP 连接、在途事务、等待者、单飞 key、缓存字节、规则文件字节/行数、组/上游数、netlink 队列和控制报文。初始候选预算见 [03](03-validation-plan.md)。

- 默认 loopback；远程监听必须显式配置，文档提示反射放大风险；单飞等待者按客户端设限。
- nft 模式需 `CAP_NET_ADMIN`，DNS 非特权端口无需绑定 53 的权限。OpenWrt 上最小权限是否可部署必须验证；不把 Linux capability 当作细粒度集合授权。
- netlink 目标只来自经验证配置，绝不拼 shell 命令。允许列表只是程序约束，不抵御拿到 CAP_NET_ADMIN 后的进程被攻陷。
- 控制 socket 默认 0600，路径父目录不可被普通用户写入；校验 peer credentials，限制连接/消息大小；不开放 TCP 管理接口。
- 不允许控制接口任意传路径或运行命令；日志默认不含查询域名、客户端 IP 或上游凭据。
- 常规故障日志按类别限流并提供 suppressed 计数；统计标签只使用配置中有界 ID，不以域名/IP 建无限标签。
- 库与依赖漏洞审计、模糊测试、恶意输入和取消路径测试是发布门槛，不以“Rust”代替安全验证。

## 10. 后续扩展原则

DoT 可作为替换资格的可选构建能力：正式候选必须提供已验证的 DoT 路径，或明确阻止使用 DoT 配置的用户迁移。不能把明文 TCP 隧道冒称原生 DoT 等价替代。

DoT 必须证书链与服务名验证，使用显式 IP + server name，根证书来源与时间不可用时的失败策略需明确；不提供默认跳过验证。

未来多出口只增加不同命名上游组及调用方策略，不让 aether-dns 读取 UCI 节点或接管节点健康。DNS 观测信息不能保证还原所有业务域名，不能成为流量分流的唯一依据。
