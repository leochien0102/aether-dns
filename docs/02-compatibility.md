# 02 兼容、nft 与迁移

## 1. 兼容对象

兼容对象是 **aether-proxy 当前实际需要的行为**，不是 ChinaDNS-NG 的全部接口。迁移通过 aether-proxy 新增 renderer/adapter 完成，不伪装成同名二进制。

现有依据是 aether-proxy `docs/03-dns.md` 与 `aether-proxy/src/lib/render/chinadns.uc`。文档与实现冲突时登记并审定，不能任取有利的一项。当前分流草案不作为既有行为。

## 2. 范围分层与行为矩阵

形态 A 是现有 nft 判定路径。形态 B 指待审定的 Xray 判定方向，不是已生效设计；原 `13-routing.md` 自身还存在 `udirect4/uproxy4` 是否参与拦截的矛盾。下表的“可移除”都以明确改变调用方契约为条件。

| 能力 | 形态 A（现状） | 形态 B（未来，未定稿） |
|---|---|---|
| 命名组、UDP/TCP 转发、缓存、过滤、boot | 通用核心，替换必须 | 通常仍需；精确解析策略待定 |
| 地域分类 + 双组选择 | 保留当前绕过大陆 DNS 行为时需要 | **不因业务路由移进 Xray 自动消失**；只有决定更改 DNS 解析策略后可移除 |
| gfw4 填充 | GFW 模式/设备覆盖所需 | Xray 完整接管且不再引用该集合后可移除 |
| uproxy4/udirect4 写入 | 现有自定义域名语义所需 | 原草案仍保留相关语义，不能预先删除；需明确迁移成 Xray 规则 |
| 集合写入屏障/重建同步 | 存在动态写入时需要 | 所有 DNS 写集合契约都删除后才可移除 |
| IPv6 分类过滤、DoT 等扩展 | 按实际配置决定迁移资格 | 同样按实际配置决定，不能由 A/B 标签推断 |

通用核心默认不依赖 netlink/CAP_NET_ADMIN。分类、双组选择与集合写入归独立可选兼容层；形态未定时只批准 P1 骨架，不提前实现该兼容层。若仍希望独立替换现有引擎，形态 A 的需求不会因为分流不急而自然失效。

以下详细矩阵仅为 **形态 A 的替换资格**，不是对所有未来部署强加的要求。

| 当前功能 | aether-dns 目标 | 资格 |
|---|---|---|
| dnsmasq → loopback 31053 | 同端口可配置、UDP/TCP 监听 | 替换必须 |
| 国内/可信组、多上游竞争 | 命名组并发竞争；不跨信任等级混组 | 替换必须；错误应答竞争策略需对照 |
| GFW 模式 | gfw 后缀 → trust，其他 → china；gfw 应答写 gfw4 | 替换必须 |
| 绕过大陆 | gfw → trust，chn/Apple → china，其他双组选择 | 替换必须 |
| 全局模式 | Apple → china，其他 → trust；DNS 不决定 Apple 流量直连 | 替换必须 |
| gfw 设备覆盖/降级 | 无论默认模式为何，按 renderer 需要填 gfw4 | 替换必须 |
| uproxy / udirect | 独立组，分别写 uproxy4 / udirect4 | 替换必须 |
| boot | 节点域名用独立引导组，不依赖 Xray | 替换必须 |
| AAAA / HTTPS 全局过滤 | 当前集成配置：本地 NODATA，允许分别开关 | 形态 A 替换必须 |
| AAAA 按组/按地域条件过滤 | 上游已有但当前 adapter 不生成；未来扩展，不合并成全局布尔 | 非当前替换必须；支持该配置前单独验收 |
| TCP / UDP 可信 DNS | 显式连接本地 Xray tunnel，相互独立协议 | 替换必须 |
| WAN DNS | 调用方展开后传 IP，不读取 ubus | 替换必须 |
| T1/T2/T3 | 调用方替换 trust 与 uproxy 上游，明确 reload ACK | 替换必须 |
| IPv4 分类/动态集合 | 分类数据源独立选型；写入 ACK、失败与重建同步 | 形态 A 替换必须 |
| stale 应答 | 正应答 TTL=0 + 后台刷新，有期限 | 替换必须；详细 TTL 差异需审定 |
| verdict-cache | 第一版暂不启用 | 显式差异，量化查询/内存开销 |
| 原生 DoT | 验证证书的可选能力，或迁移前拒绝该用户配置 | 条件替换必须 |
| IPv6 上游/AAAA 未过滤 | 不等于代理 IPv6；独立验收 | 首版范围待确认，未覆盖配置不得迁移 |
| ipset/fw3、旧缓存 DB、全部 CLI | 不支持 | 非目标 |

## 3. 域名优先级不能错误简化

ChinaDNS-NG 的域名最长后缀优先；组加载优先级主要用于**完全相同后缀的归属**。上游 `src/dnl.c` 与 README 都支持这一点。

兼容 adapter 建议使用：boot > udirect > uproxy > gfw > chn 的同键 priority，但保留最长后缀优先。用以下场景强制验证：

| 输入 | 预期 |
|---|---|
| gfw 有 `example.test`，chn 有 `api.example.test` | `api.example.test` 用更具体的 chn |
| boot / uproxy 都有 `node.example.test` | 同后缀 boot 优先 |
| boot 有 `example.test`，uproxy 有 `api.example.test` | `api.example.test` 仍用更具体的 uproxy |
| 节点实际为 `api.example.test` | adapter 生成该精确节点名引导规则，不能只靠父域名 boot |
| 同域名在 direct / proxy 列表 | 同键 direct 优先；保留可见冲突提示 |

新引擎支持完整协议长度，不继承上游超过 8 级域名时的静默截断。旧规则中受此行为影响的项需在迁移检查中报告。

## 4. nft 分类与写入

### 4.1 分类选择

`Classifier` 与 `nft_writer` 分开。P0 在实时内核 GETSETELEM 与调用方提供的同源 CIDR 快照之间选择；不采用每查询 shell 命令或周期 dump 作为默认路径。

第一轮审查 B2 声称 `ops->get()` 仅精确匹配，**源码反证表明这个普遍结论不成立**：Linux v6.18.52 的 rbtree 后端 `nft_rbtree_get()` 使用 `nft_array_get_cmp()`，在无 END flag 时接受 `from <= key < to`。ChinaDNS-NG 固定基线也发送 GETSETELEM 做成员测试。因此不把相关原型称为“注定失败”，但仍需对实际目标内核/所选 set 后端做隔离实测，源码不是运行证明。链接见 [审查答复](review/2026-11-02-response.md#b2不接受内核不支持的事实结论保留后端选型)。

同源快照是合理候选：调用方提供规范化 CIDR、内容 SHA-256 与应用代次，nft renderer 和 DNS 引擎消费同一不可变输入。**同源/同哈希不等于应用时刻原子一致，不能声称 skew 归零**；需要停止/屏障查询、应用两侧、确认代次、失败回滚后再放行。还须检测非合作手工表修改，无法强一致的窗口如实记录。

形态 A 的 P2 分别验证所选分类后端的边界、并发/期限、集合替换和数据代次，以及写入 ACK；未选定时不得同时开发两个正式后端。

分类失败选择可信组；可信不可用则 SERVFAIL。仅因分类器故障，不把域名静默判成国内。

### 4.2 写入顺序与失败

- 目标表/集合必须已经存在且类型匹配；aether-dns 不创建、flush、删除调用方表。
- interval 单点表示按实际内核行为验证，不照抄“写一个 IPv4 元素一定可用”的假设。
- 解析应答 → 选择结果 → 计算关联地址 → **写集合并确认 ACK** → 返回客户端。
- 对会影响 GFW 代理/自定义路由的写入，第一版建议 required：失败返回 SERVFAIL；绝不先回 DNS 成功、后台无限重试。
- 必需集合启动时缺失：启动失败。运行中 required 模式缺失：仅影响依赖该集合的查询，状态降级并记有界错误，其他国内/引导查询继续。
- **不把 ENOENT 自动等同 fail-open**：缺一个集合而拦截链仍在，与整表已删除是不同故障。EPERM、容量满、超时同样不能静默放行。外层只有确认已摘除相关拦截、策略允许放行后，才能通过完整新配置显式关闭写入要求；恢复时先验证/同步集合，再恢复强制写入与拦截。全局/固定出口的泄漏取舍必须继承调用方策略。
- 重复地址写入必须可重入；处理 EEXIST 不等于吞掉其他错误。集合写入与整个 DNS 查询共用截止时间。
- 不对未选中应答执行写入；不把 NXDOMAIN/NODATA/超时缓存为集合成功。

required 写入会将部分 DNS 可用性与内核集合挂钩，这是与旧实现可能不同的**有意安全取舍，待审定**。它防止客户端拿到地址后按错误出口访问，但不能撤回客户端已缓存的地址。

### 4.3 生命周期、缓存与集合重建

首版保留现有动态集合“由 aether-proxy 导出恢复、不按 DNS TTL 自动删除”的语义，避免擅自删除多个域名共享的 IP。内核元素容量必须受控，容量/内存达到上限返回明确错误；这是已知的陈旧 IP 风险，不宣称 TTL 一致性。

每次返回应答（包括缓存和 stale）前必须保证当前 set epoch 的写入成功。应用内可以记住已确认地址，但只能在同一 set epoch 内使用，且记录有字节上限。

aether-proxy 正常替换表时使用以下握手：

1. 外层调用进入短暂 DNS 副作用维护屏障；排空在途 netlink 写入，暂停依赖集合的新回复。
2. 按既有流程导出/替换/恢复 nft 表。
3. 调用 `sync-sets`：提升 set epoch，重新验证目标并重放当前缓存中可关联地址；有界分批完成后 ACK。
4. 放开屏障；若恢复失败，不声称整次 reload 成功，按外层回退策略处理。

屏障与 `sync-sets` 的具体控制命令属于 P2 接口定稿项。不能只做第 3 步就承诺没有竞争窗口。缓存淘汰掉且只存在 dnsmasq/客户端缓存中的地址无法重放，仍靠外层导出/恢复。

以上为 hot-v2 候选。restart-v1 可用“停止 DNS 并确认退出/副作用排空 → 导出并替换/恢复表 → 校验并启动 DNS → readiness 与外层缓存清理”取代在线屏障，代价是 DNS 中断与缓存冷启动；该次更新即便 DNS 配置哈希未变也须进入这一路径。非正常退出不能证明 netlink 副作用已排空，必须重新验证/恢复表，不仅重启进程。

手工 `fw4 flush` 等非合作修改仍存在检测窗口；事件监测 + 周期验证只能缩短窗口，无法提供跨进程强原子性。端到端测试必须覆盖，限制必须向使用者说明。

## 5. 缓存、信任等级与残留集合

T1→T3、T3→T1、域名策略变化：加载新完整配置、引擎清逻辑缓存/取消旧请求、ACK 后外层清 dnsmasq 缓存。不能合并不同等级同组竞争来伪装回退。

引擎清缓存**不会**删除已经写入 nft 的污染 IP，也不会清客户端缓存。首版保持旧集合管理边界；污染地址可能继续影响路由，是已知限制。若未来要按信任代次清理，必须解决地址共享/所有权/连接影响并单独设计。

外层 T2 探测默认被墙域名、探测被缓存掩盖等既有问题，由 aether-proxy 另行修订；不让新 DNS 引擎暗中改变健康状态机。

## 6. 迁移顺序

### 6.1 集成接口候选契约（P0 必须冻结）

以下为本稿建议，不是已实现接口。**首次集成使用 restart-v1，hot-v2 另行批准**；控制接口不可悄悄换掉现有回滚模型。

| 集成点 | restart-v1 建议契约与失败动作 |
|---|---|
| 启动 argv | `[binary, "run", "-c", absolute_config]`，前台运行；非 0 退出交外层处理 |
| 离线校验 | `[binary, "check", "-c", staged_config, "--json"]`；失败不发布配置、不改当前进程 |
| 配置/hash 输入 | schema 版本、规范化 JSON、所有引用规则/CIDR 文件内容 hash、渲染器版本、引擎版本；不可变版本目录，不能只 hash JSON 路径 |
| 配置代次 | 外层生成的不重复应用 ID + 内容 hash；通过状态读取确认，不将内容 hash 当单调计数 |
| 变化应用 | 先校验 staging，再停止旧子进程并确认退出，按副作用约束更新 nft，启动新进程；保留旧 artifact 与旧 binary |
| readiness | 既有端口探测只作存活初筛；通过离线固定的合成 readiness 查询检查 UDP/TCP 响应，再核对状态应用 ID/hash；不依赖公网健康。状态通道最小只读接口在 P0 定稿 |
| 新进程失败 | 停止新进程，恢复旧 artifacts/二进制及必要 nft 状态，重启旧引擎并再次验证 readiness；任何恢复步骤失败则进入外层 DNS 故障恢复，不误报成功 |
| 运行中死亡 | monitor 按现有 DNS 子进程故障路径处理并移除/恢复片段；具体重试/回退由外层负责，不由引擎擅自直连 |
| 外层缓存 | 新实例 readiness 后执行 dnsmasq HUP；失败记整体未完成，尝试既定恢复并明确报告失败 |
| nft-only 更新 | 有 DNS 写入时也需暂停/停止 DNS，不能因 DNS hash 未变化而跳过副作用协调 |

hot-v2 的额外冻结项：expected generation 不符拒绝且无副作用；提交前失败保留旧代；socket 断开/响应丢失返回“结果未知”，调用方先读取状态确认新旧代，再决定恢复，不盲重发；旧 netlink 副作用无法撤销时必须协调表恢复。此接口未验收前 adapter 不使用在线 reload。

### 6.2 切换步骤

1. 先完成标准配置、可复现构建、行为测试和内核集成，不改正式服务。
2. aether-proxy 增加引擎 adapter：配置渲染、precheck、生命周期、状态、restart-v1 与回滚；不同时改流量分流或接入未经验证的 hot-v2。
3. 在隔离测试环境用相同伪上游并行对照，不向生产 nft 集合双写；无需公网查询真实用户域名。
4. 在获准维护窗口切换；监听相同入口，不让两个引擎竞争端口。带期限、自动回退和完整清理。
5. 验证全部模式、设备覆盖、DNS 等级、重载/停止恢复、节点切换、集合重建后，再考虑默认启用。

新引擎失败不能自动进入“国内 DNS 直连”或擅自切换旧引擎。回退由外层按已验证完整配置执行：停止新进程、恢复旧配置/引擎、确认 DNS 成功、恢复外层状态。升级前保留旧二进制与已知良好配置；不复用两种引擎的缓存格式。

## 7. 尚待审定的行为变化

| 行为 | 已核对现状 | 本稿建议 / 差异类别 |
|---|---|---|
| 多地址分类 | answer 第一条 A/AAAA 决定 | 链关联地址全部命中；建议有意修正，待批 |
| 地址 owner/CNAME | test_ip/add_ip 不核对 owner 链 | 分类/写集合只用链可达地址；建议有意修正，待批 |
| 国内 NODATA | 默认关闭 noip-as-chnip 时选 trust | 保持 |
| AAAA/HTTPS 全局过滤 | empty_reply，NOERROR/NODATA | 保持当前集成用法；不声称覆盖上游按组/分类过滤 |
| 国内 TC | 有接受截断应答分支 | 先 TCP 补全再分类；建议有意修正，待批 |
| >8 级域名 | 规则加载静默截断 | 不截断，迁移检查提示；建议有意修正，待批 |

上述为源码核对，不是新引擎对照实测。混合 A 的新规则会改变解析结果，流量出口取决于随后 nft 策略，不能笼统断言“选国内一定直连、选 trust 一定代理”。TC/EDNS、缓存命中写集合、超时/错误竞争还需固定基线实验。

所有差异按“必须等价 / 有意修正 / 不支持并阻止迁移”登记。替换前不允许有未分类差异。
