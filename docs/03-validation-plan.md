# 03 验证、构建与实施计划

本文所有工具、流程和数值均为方案，不代表已经运行过测试。当前仓库只有文档。

## 1. 阶段与停止条件

| 阶段 | 交付 | 放行条件 / 停止条件 |
|---|---|---|
| P0 规格与依赖调查 | 审定范围/差异，固定上游基线、依赖与许可证候选清单 | 关键语义或许可未定，不进入完整实现 |
| P1 Rust 最小原型 | UDP/TCP echo-style DNS 转发、协议库验证、有界任务与连接 | x86_64/aarch64 交叉构建、报文正确、资源可接受；失败先调整选型 |
| P2 策略与 nft 风险原型 | 最长匹配、双组选择状态机、真实 interval 集合与重建握手 | 特权测试证明读/写/ACK/重建正确；不可维护时重新审查后端 |
| P3 替换所需引擎 | 缓存、过滤、重载、状态、资源保护、DoT 资格处理 | 行为矩阵无未分类差异；安全和稳定性闸门通过 |
| P4 OpenWrt 集成 | 包、adapter、生命周期、完整回退与隔离环境测试 | 目标发行版/架构验收，不改多出口分流 |
| P5 真机与候选发布 | 维护窗口、压力/长稳数据、签名包、回退演练 | 所有者批准才改变默认依赖 |

不预估日历工期，不把某个阶段“代码完成”当作已满足替换资格。

## 2. 第一批可证伪实验

1. **构建**：固定 stable Rust 的具体版本，冷/热构建各测三次；x86_64 与 aarch64 musl 目标都产物可运行，不把“rustup 能添加 target”当成交叉链接成功。
2. **协议库**：未知 RR、压缩指针、CNAME、EDNS、大应答、TCP 分段与截断安全重编码。不能安全支持目标协议则更换库或缩小可迁移范围。
3. **运行时**：单 worker 在慢上游、大并发、取消与压力下是否阻塞国内查询；netlink 不得阻塞 runtime。
4. **nft**：真实内核上的 interval 单点/边界、set 类型、元素去重、ACK/错误、整表替换与缓存重放。
5. **重载**：旧请求迟到、旧 netlink ACK 迟到、外层 dnsmasq 缓存清理失败，不能误报整体成功。
6. **传输成本**：对比每查询建连接与有界连接复用；真实 Xray tunnel 的 TCP/UDP 出口协议各验证，不能只跑配置语法检查。

## 3. 对照测试的边界

固定 ChinaDNS-NG 源码 commit、构建工具链、feature、二进制哈希。P0 前未固定，现有上游 master 只是调研引用。

同一组确定性伪上游先后或隔离并行运行两个实现，记录请求路径、应答语义、时序和集合变化。忽略随机 ID、源端口等非语义差异；TTL 允许明确时钟误差，不忽略路由/信任差异。

不能直接以旧程序输出作为唯一正确答案：已知缺陷与 RFC 要求分别列出。所有不一致必须归类并经审查，不能改断言迎合新实现。

## 4. 必测场景

| 领域 | 代表场景与断言 |
|---|---|
| 匹配 | 精确/后缀/标签边界/最长匹配/同键 priority/大小写/结尾点/超过 8 级 |
| 模式 | gfw/bypass/global，Apple、udirect/uproxy/boot，gfw 设备覆盖与降级 |
| 双组 | china 先/后；混合 A；CNAME；无关 additional；非 A；可信先返后等待；分类失败 |
| 应答校验 | ID/问题/端点错误、重复/迟到、NXDOMAIN/NODATA、SERVFAIL 抢答、损坏包 |
| wire | 指针环/越界、恶意计数、截断、未知 RR、EDNS/DO/CD、TC 重试、TCP 长度/半关闭/分段 |
| 缓存 | key 隔离、TTL 递减、零 TTL、stale 上下边界、单飞、等待者上限、配置变更不回填 |
| 资源 | 超过硬限、不响应上游、国内预算隔离、FD 关闭、取消释放、内存峰值、队列溢出 |
| nft | 真实集合写入而非只启动进程；缓存命中重写、EEXIST/ENOENT/EPERM/容量满、ACK 超时 |
| 重载 | 错配置保留旧代、冲突代次拒绝、部分文件失败、旧写入排空失败、屏障恢复失败 |
| 生命周期 | 启停、崩溃、引导 DNS 无循环、清外层缓存失败、自动回退、无残留服务 |
| 隐私 | 默认日志无域名/客户端地址，错误限流，管理 socket 非授权访问失败 |
| DoT（如启用） | CA/主机名/过期证书失败、时间异常、根证书缺失，不绕过验证 |

恶意输入仅在本地/隔离环境测试，不向第三方 DNS 发送畸形包。

变异测试重点：去掉最长匹配、把全部 IP 改成任一 IP、允许错误 ID、跳过 set ACK、移除代次检查、抬高 TTL、取消超时、允许旧配置回填。每个关键不变量至少有能杀死对应变异的测试。

## 5. 候选资源预算（审查用，不是承诺）

测试集至少包括：空规则、5k 后缀、120k 后缀、4096 缓存条目；正/负/大应答和慢上游混合。分别报告配置加载、稳态和 reload 双快照峰值，不只给平均值。

| 项目 | 第一版候选值 |
|---|---|
| 引擎内存 | 120k 规则+满缓存场景 RSS ≤32 MiB，重载峰值 ≤64 MiB；P1/P2 根据实测审定 |
| 应答缓存 | 默认 4096 条，同时限制负载字节 8 MiB；负载不包含全部 Rust/索引开销 |
| 在途查询 | 全局 256，按国内/引导与可信分配保留额度；未用额度借用规则需明确 |
| 每组上游 | 默认最多 4，硬上限 8；配置组默认最多 32 |
| 查询整体期限 | 默认 3 秒，配置范围建议 100 ms–10 秒 |
| 客户端/上游连接 | 各默认上限 64，单连接在途/空闲时间分别受限 |
| 控制报文 | 单条 ≤64 KiB，控制连接最多 4 |
| DNS wire | 支持协议长度边界，UDP 输出默认上限 1232；大 TCP 缓冲按需分配且计入预算 |

上述数值不能用来宣称支持所有 16–128 MiB 设备。首轮资格目标为 x86_64/aarch64、可支配内存至少 128 MiB 的测试环境；更低资源目标需单独定义并验证。所有者需要确认支持范围。

性能报告：空载/满载 RSS、FD、二进制与压缩包体积；启动/重载 p50/p95；缓存命中与转发 p50/p95/p99；持续 QPS 与丢包/失败比例；UDP/TCP/真实 tunnel 分开统计。给硬件、版本、参数、原始数据与复现步骤，不能用宿主机数字代替设备结果。

长稳候选门槛：至少 24 小时混合负载与重复 reload，无持续增长的在途任务/FD/内存；执行压力后回落检查，允许分配器保留内存但需说明。是否进一步要求 72 小时由发布审查决定。

## 6. 构建与发布

- 独立仓库、独立版本，aether-proxy 固定依赖已验证版本，不因应用前端修改重编 Rust。
- 固定 `rust-toolchain.toml` 具体 stable、提交 `Cargo.lock`、默认 feature 显式控制、`--locked`；此阶段尚不指定未经验证版本。
- Cargo 缓存 key 包括工具链、target、锁文件、profile/features；缓存只加速，不成为可构建前提。冷构建必须定期验证。
- 优先尝试 Rust target + 对应 OpenWrt SDK linker/sysroot 的源构建路线；musl 静态构建作为可分发候选，不预先承诺全部架构无需 C 工具链或全部静态可行。
- 基线先 x86_64/aarch64，再按 OpenWrt 包架构、CPU 指令、端序、ABI 明确扩展；不笼统承诺 MIPS/ARM32 全支持。
- 开发 profile 不追求极限体积；发布评估 thin LTO/strip/codegen units 的实际成本，不同时维护大量 profile。
- 完成源码构建包和预编译包消费路线：源码构建给固件维护者可重现路径，预编译包让日常应用发布不重复编译。
- SDK/包格式从构建配置或真实工具探测，不按系统版本号猜测 ipk/apk、Rust 或 nft 能力。
- CI 分非特权单测/协议测试、隔离特权 netlink 测试、跨架构构建运行、依赖漏洞与许可证检查。QEMU 不替代实际目标设备。
- 每个候选产物发布源码版本、锁文件、工具链/SDK、features、依赖清单/SBOM、哈希与签名；保留对应源码可获取性。
- PR 无发布密钥；正式发布另设权限门槛。具体签名方案与 aether-proxy 发布通道集成需单独审定，不自动沿用其他仓库私钥。

## 7. 真机测试纪律

没有所有者批准，不连接或修改实际出口路由。先隔离环境；真机维护窗口需说明影响、限时、自动恢复旧服务、带外/本地回退办法。窗口后逐项确认 DNS、防火墙、原服务、临时文件与子进程状态。

替换默认引擎的最终门槛：兼容矩阵全覆盖、差异全部审定、原生/可选特性迁移检查到位、故障与回退实测、安全/资源测试通过、所有者明确批准。
